# sormick Cloud — PC virtuel

Un mini Windows dans le navigateur : bureau, barre des tâches, App Store, stockages WebDAV, lecteurs intégrés (musique, vidéo + sous-titres, documents Office/PDF/TXT, images), éditeur de texte enrichi, plusieurs utilisateurs.
Le site fonctionne **sur GitHub Pages**. Services externes : le **relais Cloudflare** (à vous, pour joindre les WebDAV sans CORS) et, facultatif, OpenSubtitles pour les sous-titres. **SFTP n'est pas pris en charge** : un navigateur ne sait pas parler SFTP ; utilisez WebDAV.

## Publier
Settings → Pages → *Deploy from a branch* → `main` / `/ (root)`. Le site s'ouvre sur `https://<utilisateur>.github.io/<dépôt>/` (pas sur la page du dépôt).

## Utilisateurs et confidentialité (dépôt public)
- Le dépôt ne contient **que du code** : aucune donnée personnelle.
- Chaque utilisateur a son bureau, ses raccourcis de bureau, son fond, ses connexions WebDAV, ses playlists et ses documents. Le **catalogue de l'App Store est propre à chaque utilisateur**.
- Les données d'un utilisateur sont **chiffrées dans le navigateur** (AES-256-GCM). La clé est dérivée de son mot de passe (PBKDF2-SHA256, 600 000 itérations, sel aléatoire) et n'existe qu'en mémoire pendant la session. Les mots de passe WebDAV et OpenSubtitles sont dans ce profil chiffré : une fois enregistrés, ils ne sont plus redemandés.
- Sont stockés **en clair** sur l'appareil, par utilisateur : le **catalogue de l'App Store** (noms, adresses, descriptions), l'**avatar**, les **miniatures de la playlist** et le **PDF du tutoriel**, ainsi que la liste des noms d'utilisateurs. Les liens et titres de la playlist, le fond d'écran personnalisé, les connexions, les Post-it… restent dans le profil chiffré. Ne mettez rien de confidentiel dans une description d'application, une miniature ou le PDF.
- Le mot de passe d'un utilisateur **ne peut pas être récupéré** (il n'existe aucun serveur). En cas d'oubli, le profil est perdu.
- Les données restent **dans le navigateur de cet appareil** (le site demande au navigateur de ne pas les effacer). Pour les retrouver sur un autre ordinateur, deux moyens :
  - **Sauvegarde dans votre cloud WebDAV** (recommandé) : *Mon compte → Sauvegarde dans mon cloud* : choisissez un de vos lecteurs, puis *Sauvegarder maintenant* (ou cochez la sauvegarde automatique : 1 minute après une modification et au verrouillage). Un dossier `sormick-cloud` est créé : `sormick-<id>.profil.json` (profil **chiffré** + catalogue, nom et avatar en clair) et `sormick-<id>.media.json` (miniatures et PDF en clair). Un bouton **Sauvegarder maintenant dans mon cloud** est toujours visible dans *Mon compte*, et **au verrouillage** (bouton « Verrouiller / changer d'utilisateur ») l'application propose de sauvegarder si des données ont changé depuis la dernière sauvegarde (« Sauvegarder et verrouiller » / « Verrouiller sans sauvegarder » / « Annuler » ; pas de question si la sauvegarde automatique est cochée ni pour le verrouillage par inactivité). Sur le nouvel ordinateur : écran de connexion → **Restaurer depuis mon cloud** (adresse, utilisateur et mot de passe du cloud, relais si besoin), puis connexion avec le mot de passe du profil. Le fond d'écran personnalisé, la playlist, les connexions, les Post-it, la clé API et le compte OpenSubtitles suivent (tout cela est dans le profil chiffré). **La dernière sauvegarde remplace la précédente** (pas de fusion entre deux ordinateurs). Le fichier du profil reste inutilisable sans votre mot de passe ; le reste est lisible par quiconque accède à ce dossier du cloud.
  - **Export des profils (seul export vers l'ordinateur)** (*Mon compte → Exporter tous mes profils (chiffrés)*) : un fichier `sormick-profils.json` contenant **tous les profils de l'appareil** avec leurs connexions cloud (mots de passe WebDAV), relais et jetons. Chaque profil (avec ses clouds, relais, jetons et la clé API / le compte OpenSubtitles) reste chiffré par son mot de passe, et l'ensemble est **chiffré une seconde fois par un « mot de passe d'export »** (8 caractères minimum, choisi à l'export, PBKDF2 600 000 itérations + AES-GCM, non récupérable) **redemandé à l'import**. Sur le nouvel ordinateur : **Importer un profil** (écran de connexion ou tout premier écran) → mot de passe d'export → chaque profil se déverrouille avec son propre mot de passe → l'application propose de **récupérer raccourcis, playlist (miniatures) et PDF du tutoriel dans le cloud déjà connecté** de ce profil. Tant que ce n'est pas fait (ou ignoré), les sauvegardes de ce profil sont suspendues pour ne pas écraser celles du cloud. Récupération manuelle à tout moment : *Mon compte → Sauvegarde dans mon cloud → Récupérer mes données depuis le cloud*. Cette récupération **fusionne sans rien supprimer** : elle ajoute les raccourcis, miniatures et PDF, mais aussi ce qui est plus récent dans la sauvegarde que dans le fichier de profils importé (**post-it**, liens de la playlist, playlists musique, documents, clouds, relais, clé OpenSubtitles) ; un post-it présent des deux côtés garde la version la plus récente, et un réglage unique (fond d'écran, relais déjà saisi) n'est pas écrasé. Si le mot de passe du profil a changé depuis la sauvegarde, il est redemandé. **Tout le reste passe par le cloud** : aucun export de raccourcis, playlist, miniatures ni PDF vers l'ordinateur. Les anciens fichiers d'un seul profil restent importables.
  - **Fiabilité de la sauvegarde automatique** : chaque envoi au cloud a un délai maximal (un cloud qui ne répond plus ne bloque plus les sauvegardes suivantes) ; en cas d'échec, le message donne la raison, un nouvel essai a lieu 5 minutes plus tard, et le bouton de sauvegarde de la barre passe en orange. « Modifié depuis la dernière sauvegarde » est mémorisé sur l'appareil : une sauvegarde manquée ou un onglet fermé trop tôt est rattrapé à la connexion suivante. Un contrôle toutes les minutes relance la sauvegarde si le minuteur a été perdu (veille de l'ordinateur). *Mon compte* indique « tout est à jour », « des modifications ne sont pas encore sauvegardées » ou la raison du dernier échec. Le bouton **Sauvegarder maintenant** (Mon compte et barre) répond « Déjà sauvegardé » avec la date quand rien n'a changé (avec un bouton pour sauvegarder quand même).
  - **Profil importé et cloud vide** : si le lecteur de sauvegarde choisi n'a aucune sauvegarde de ce profil (dossier « sormick-cloud » absent, ou sans fichier de ce profil), il n'y a rien à récupérer ni à écraser : la suspension est levée automatiquement et la première sauvegarde démarre (à la connexion, en choisissant le lecteur, avec « Sauvegarder maintenant » ou « Récupérer mes données »). Le lecteur de sauvegarde choisi (et la sauvegarde automatique) font partie du profil et sont retrouvés avec lui. Après chaque envoi, le site vérifie que les fichiers sont bien dans le dossier du cloud et signale l'erreur sinon.
  - **Copie de secours** : après chaque sauvegarde réussie, les mêmes fichiers sont aussi envoyés ailleurs (*Mon compte → Copie de secours*) : « Automatique » = un autre cloud connecté s'il y en a un, sinon le dossier « sormick-cloud-secours » du même cloud ; ou un cloud de votre choix ; ou aucune. Si le dossier principal est vide ou effacé, « Récupérer mes données » reprend automatiquement depuis la copie. L'échec de la copie n'annule pas la sauvegarde mais est signalé.
  - **Cloud principal en panne** : la copie de secours est quand même envoyée (message « vos données sont à l’abri ») ; la sauvegarde principale est réessayée toute seule toutes les 5 minutes, et un échec de la copie seule est aussi réessayé. À la récupération, si le cloud principal est injoignable ou vide, les données sont lues dans la copie de secours.
  - **Alerte visible en cas d'échec** : bandeau rouge persistant en haut de l'écran (« Vos données ne sont PAS sauvegardées » + raison, boutons « Réessayer maintenant » et « Mon compte »), bouton de sauvegarde de la barre rouge clignotant, ⚠ dans l'onglet du navigateur. L'alerte disparaît dès que la sauvegarde réussit ; elle apparaît aussi si la sauvegarde automatique n'a rien envoyé depuis plus de 6 h alors que des modifications attendent.
- Verrouillage automatique après inactivité (réglable), ou **immédiat avec le raccourci clavier Alt + L** (sans question ; la sauvegarde automatique, si elle est cochée, est faite avant). Sur un ordinateur partagé, verrouillez la session ou videz les données du site.
- Limite honnête : ce n'est pas une protection contre quelqu'un qui contrôle déjà votre navigateur ou votre ordinateur ; choisissez un mot de passe long.

## WebDAV : adresse + utilisateur + mot de passe
**Diagnostic** : le bouton *Diagnostic* (cartes des lecteurs, et dans un dossier affiché vide) montre ce que le serveur répond réellement à la liste d'un dossier : adresse demandée, mode d'accès (direct ou relais), code HTTP, type de réponse, nombre d'entrées et leurs noms. Le mot de passe ou le jeton n'est jamais affiché (seulement sa longueur) ; le texte est copiable. Si le serveur répond autre chose que du WebDAV, une erreur claire s'affiche au lieu d'un dossier vide.

Dans *Stockage cloud*, trois champs suffisent : l'adresse du serveur, l'utilisateur, le mot de passe. L'application teste la connexion, l'enregistre (chiffrée) et ouvre l'explorateur ; vous ne la ressaisissez plus jamais. Le nom est déduit de l'adresse (modifiable dans *Options*), `https://` est ajouté si vous l'oubliez.
- **Aucun réglage CORS, aucun bouton à cliquer** : l'application essaie d'abord en direct ; si le navigateur refuse, elle **bascule toute seule par le relais** (voir ci-dessous) et s'en souvient pour cette connexion (lecture en continu et envoi de fichiers compris). L'adresse et le jeton du relais se saisissent **une fois** dans l'application (*Stockages cloud → Relais…* ou clic droit sur le bureau → *Relais…*), jamais dans le dépôt.
- **Site du fournisseur et icône** (*Options*, facultatif) : l'adresse du site officiel de votre cloud. L'**icône** du fournisseur est détectée automatiquement (comme pour les apps : `favicon.ico` du site, puis service d'icônes DuckDuckGo si activé) ; sinon importez la vôtre (*Importer une icône…*). Elle remplace le nuage par défaut sur la carte du stockage, l'accès rapide et le raccourci du bureau. Chaque explorateur et chaque lecteur (musique, vidéo, documents, images, sélecteur cloud) a alors un bouton **Mon cloud (site officiel)** qui l'ouvre dans un nouvel onglet. Seules les adresses `https://` sont acceptées.
- **Explorateur** : cases à cocher, **Supprimer** (un ou plusieurs fichiers/dossiers, avec confirmation explicite ; un dossier est supprimé avec son contenu), **Déplacer…** et **Copier…** (choix du dossier de destination dans une fenêtre ; jamais d'écrasement : un élément du même nom est refusé ; un dossier ne peut pas être placé dans lui-même ; WebDAV `MOVE`/`COPY`), **Nouveau dossier**, **Nouveau texte**, **Téléverser ici**, **Raccourci bureau** (icône du stockage sur le bureau). Un clic ouvre le fichier dans le bon lecteur ; si aucun lecteur ne le prend en charge, l'application **demande avant de le télécharger** (rien n'est téléchargé sans accord). Pas de miniatures : la navigation reste rapide. **Recherche** : une barre en haut cherche par nom (insensible aux majuscules et aux accents, plusieurs mots possibles) soit dans le **dossier actuel** (filtre instantané), soit dans **tout le lecteur** (parcours des dossiers, 3 à la fois, bouton *Arrêter*, limites de 500 résultats et 3 000 dossiers ; chaque résultat indique son dossier, un clic l'ouvre, le bouton *Dossier* y emmène). Sur un gros lecteur, la recherche globale peut être longue et utilise beaucoup de requêtes (donc du quota du relais si vous l'utilisez). Les boutons « Fichier local » et « Lire le dossier » n'existent que dans les lecteurs concernés.
- Les stockages ne s'ouvrent jamais dans un nouvel onglet ; SFTP n'est pas pris en charge (voir plus bas).
- Diagnostic en cas d'échec : *serveur injoignable* (adresse, réseau, certificat), *identifiants refusés (401)*, *dossier introuvable (404)*. Serveur sur **réseau local** (NAS) : le relais, situé dans le cloud, ne peut pas l'atteindre ; l'accès direct exige alors un réglage CORS côté serveur (origine `https://<utilisateur>.github.io` autorisée, méthodes `GET, PUT, DELETE, MKCOL, PROPFIND, OPTIONS`, en-têtes `Authorization, Depth, Range`).

## Relais : se connecter à un WebDAV tiers sans réglage serveur
Si vous ne contrôlez pas le serveur WebDAV (fournisseur cloud, entreprise, hébergeur), il ne peut pas recevoir le réglage CORS. Solution : un **relais** à vous, déployé **une seule fois** (`worker.js`), qui fait les requêtes à la place du navigateur.

**Mise en place (≈ 5 minutes, offre gratuite de Cloudflare)**
1. Compte gratuit sur [cloudflare.com](https://dash.cloudflare.com/sign-up).
2. *Workers & Pages* → *Create* → *Create Worker* → nom au choix → *Deploy*.
3. *Edit code* : tout remplacer par le contenu de `worker.js`, vérifier `const SITE = 'https://…github.io'` (sans `/` final), *Deploy*.
4. **Verrouiller par jeton (recommandé)** : dans l'application, *Stockages cloud → Relais…* → *Générer un jeton* → *Copier le jeton*. Dans Cloudflare : *Settings → Variables and Secrets → Add* → type **Secret**, nom **`RELAY_TOKEN`**, valeur = le jeton → *Deploy*.
5. Dans l'application (même fenêtre *Relais*) : collez l'adresse du Worker (`https://…workers.dev`) et le jeton → *Tester* (« Relais joignable et verrouillé ») → *Enregistrer*. L'adresse et le jeton sont enregistrés **chiffrés dans votre profil** ; `config.js` reste vide (`RELAY_URL = ''`).

**Ce que le relais fait et ne fait pas**
- Sans le secret `RELAY_TOKEN`, il n'exige rien de plus que le contrôle du site d'origine ; **avec** le secret, toute requête sans le bon jeton (en-tête `X-Relay-Token`, comparaison à durée constante) est refusée : connaître l'adresse du relais ne suffit plus. Le bouton *Tester* signale si le relais est resté ouvert.
- Il ne répond qu'aux pages de votre site (en-tête `Origin`) et ne relaie que des adresses **https:// publiques** (pas d'IP, pas de `localhost`, pas de réseau privé). Redirections revérifiées, l'identifiant n'est jamais envoyé à un autre hôte. Le jeton n'est pas transmis au serveur WebDAV.
- Il ne stocke ni ne journalise rien dans son code ; l'en-tête d'identification est transmis tel quel au serveur WebDAV.
- **Limites, dites honnêtement** : vos identifiants et vos fichiers **transitent pour le relais** (en HTTPS jusqu'à lui et depuis lui) : il appartient à votre compte Cloudflare, mais il faut lui faire confiance. Le jeton est stocké dans votre profil chiffré et envoyé avec chaque requête ; si quelqu'un contrôle déjà votre navigateur ou du code exécuté dans votre session, il peut le lire (voir « Contributions externes »). Changez-le en cas de doute (nouveau secret dans Cloudflare + *Relais…*).
- Certains hébergeurs bloquent les adresses de Cloudflare : la connexion échoue alors même avec le relais. Un site peut aussi limiter les échecs de mot de passe : utilisez un mot de passe d'application si le fournisseur en propose.

## Pourquoi pas SFTP ?
SFTP est un protocole SSH, pas une requête web : **aucun navigateur ne peut l'ouvrir**. Il a donc été retiré. Si vos fichiers sont derrière SFTP, exposez le même dossier en WebDAV (SFTPGo propose les deux ; ou `rclone serve webdav monsftp:/ --addr :8443 --user NOM --pass MOTDEPASSE --allow-origin https://<utilisateur>.github.io --cert cert.pem --key cle.pem`, à vérifier avec `rclone serve webdav --help`).

## Applications intégrées (non supprimables)
Toujours présentes dans **Mes apps** (jamais dans l'App Store, qui ne liste que les raccourcis web) : **Lecteur de musique**, **Lecteur vidéo**, **Lecteur de documents**, **Visionneuse d'images**, **Stockage cloud**, **Éditeur de texte**, **Playlist Medias**, **Post-it**, **Sormick Radio**, **Sormick TV**, **Enregistreur d’écran**, **Dessin**. On peut seulement les retirer du bureau puis les y remettre. Chaque lecteur ouvre un fichier **depuis l'appareil** (bouton « Fichier local ») ou **depuis un stockage WebDAV** (bouton « Depuis le cloud… », navigation, sélection multiple). « Lire le dossier » n'existe que dans le lecteur de musique/vidéo/images.
- **Musique** : liste de lecture, **Vider la liste**, lecture en continu. **Pochette** et **paroles** intégrées au MP3 (étiquettes ID3v2.2/2.3/2.4 : titre, artiste, album, image APIC, paroles USLT) : la pochette s'affiche en grand dans le lecteur et le bouton **Paroles** ouvre une nouvelle fenêtre qui suit le titre en cours. Pour un fichier WebDAV, seul le début du fichier est lu (lecture partielle). **MP3 uniquement** (pas FLAC/M4A) ; sans paroles intégrées, l'application l'indique. Aucun service de paroles externe n'est interrogé.
- **Sous-titres OpenSubtitles synchronisés** : la recherche calcule l'empreinte du fichier vidéo (taille + 64 Ko du début et de la fin, lus par plage ; seules 16 caractères sont envoyées) pour trouver les sous-titres de **votre** version du film (« ✓ Synchro exacte », en tête de liste). Sinon les résultats sont classés par ressemblance de nom avec votre fichier (BluRay, WEB-DL, groupe…) puis par popularité ; une cadence (i/s) différente explique un décalage qui grandit : le décalage ± du lecteur corrige un écart constant. « Tester la connexion » vérifie clé API, identifiant et mot de passe. **Choix de la version la mieux adaptée** (toutes langues) : recherche en plusieurs passes (empreinte + identifiant IMDb du film si connu + titre/année ou saison/épisode), puis classement par empreinte exacte, même groupe de diffusion, même source (BluRay/WEB-DL…), même résolution et codec, source fiable, popularité ; les traductions automatiques sont masquées (case à décocher) ; la première ligne porte « ★ Recommandé ». **Contrôle de durée** après chargement : un sous-titre qui finit après la vidéo avec un écart de 25 → 23,976 ou 24 i/s propose une correction automatique de la vitesse ; un sous-titre beaucoup trop long ou trop court est signalé (autre version). **Bouton « Caler… »** du lecteur : indiquez quand la première puis la dernière phrase sont dites, le décalage ET la vitesse sont calculés. **Encodage selon la langue** : les anciens fichiers non UTF-8 sont lus en windows-1251 (russe…), 1256 (arabe), Shift-JIS, GBK, Big5, EUC-KR, etc. (langue lue dans OpenSubtitles ou dans le nom `film.ru.srt`).
- **Vidéo** : lecture en continu avec déplacement dans la vidéo ; sous-titres `.srt`, `.vtt`, `.ass` chargés à la main, détectés automatiquement s'ils portent le même nom dans le même dossier, décalables de ±0,5 s ; recherche **OpenSubtitles** dans **105 langues** (toutes celles de l'API : français, anglais, indonésien, mongol, tétoum / tetun dili, arabe, chinois simplifié / traditionnel / cantonais, etc. ; le français et les langues courantes sont en tête de liste) (compte et clé API gratuits, à saisir dans la fenêtre ; stockés chiffrés dans votre profil). L'accès direct à leur API dépend de leur réglage CORS : **non vérifié** depuis mon environnement (testé avec une API simulée). S'il est refusé, l'application le dit et vous pouvez charger le fichier à la main.
- **Documents** : `.docx`, `.xlsx`, `.pptx`, `.odt/.ods/.odp`, `.txt`, `.md`, `.csv`, `.json`, `.pdf` (PDF.js, mot de passe PDF géré). Affichage simplifié ; anciens formats `.doc/.xls/.ppt/.rtf` à télécharger. Documents convertis sans `innerHTML` ; XML avec DOCTYPE/ENTITY refusé ; limites de taille.
- **Images** : zoom, déplacement, rotation, plein écran, diaporama, glisser-déposer, flèches du clavier.

**Lecture en continu sans proxy** : `sw.js` (service worker de votre propre site) récupère le fichier WebDAV directement, avec vos identifiants gardés **en mémoire seulement**, par morceaux (Range). Si le serveur n'expose pas `Content-Range`, repli automatique sur un téléchargement complet.

## Connexion par clé d'accès (passkey, Windows Hello, Touch ID…)

« Mon compte » → **Activer la clé d'accès** (mot de passe demandé une fois). Ensuite l'écran de connexion propose **Se connecter avec une clé d'accès** : Windows Hello (visage, empreinte, PIN), Touch ID / Face ID, téléphone ou clé de sécurité. Le mot de passe reste valable en secours.

- Principe : l'appareil fournit, via l'extension WebAuthn « PRF », un secret propre à ce site (déverrouillage obligatoire). Ce secret chiffre une copie du mot de passe rangée dans les réglages de cet appareil ; sans la clé d'accès elle est illisible. Rien n'est envoyé à un serveur.
- Windows Hello : fonctionne sur Windows 11 24H2/25H2 à jour (mise à jour de février 2026 ou plus récente) avec Chrome/Edge 147+ ou Firefox 148+. Sur un système plus ancien, l'activation est refusée avec un message clair et le mot de passe reste utilisé.
- La clé d'accès (dans Windows Hello, le téléphone…) est propre à chaque appareil. Une copie chiffrée est aussi rangée dans votre profil : si vous effacez les données du navigateur puis restaurez votre profil et vous connectez une fois avec le mot de passe, la clé d'accès de cet appareil est retrouvée automatiquement. Sur un autre appareil, activez-la de nouveau. Le bouton « Se connecter avec une clé d'accès » n'apparaît qu'après cette première connexion par mot de passe (avant, l'écran ne connaît pas encore le profil). Une clé activée avant cette fonction est ajoutée au profil à la première connexion : refaites un export après vous être connecté une fois.
- **Plusieurs clés d'accès (une par appareil)** : sur chaque appareil (smartphone, ordinateur, TV…), « Mon compte » → **Ajouter une autre clé d'accès** (nom proposé : Smartphone, Ordinateur…, modifiable). Les clés déjà enregistrées restent valables ; 8 au maximum. L'écran de connexion propose le même bouton : l'appareil présente la clé qu'il possède. **Retirer** supprime une seule clé (le mot de passe reste valable).
- Changer le mot de passe demande une confirmation avec la clé d'accès de **cet appareil** pour la mettre à jour. Les clés des autres appareils contenaient l'ancien mot de passe : elles sont retirées et sont à réactiver sur ces appareils (un message le dit). Supprimez aussi la clé dans Windows / le navigateur / le téléphone si vous le souhaitez.

## Sormick Tchat et Konekt (messagerie et réseau social privés)

Deux applications intégrées (Mes apps → Applications intégrées), sans aucun autre serveur que **le cloud WebDAV de votre choix** (celui que vous avez déjà ajouté dans « Stockage cloud »). Chaque application guide pas à pas : choix du cloud (testé automatiquement), nom, puis un **code d'invitation** à envoyer à l'autre personne (pas de QR code).

- **Sormick Tchat** : conversations entre utilisateurs (profils et appareils différents), messages, photos, fichiers (25 Mo max.), emojis et GIF (**recherche de GIF dans une fenêtre interne** via GIPHY, ou GIF de l'appareil, ou adresse `https://`). Code d'invitation `SMC1-…`.
- **Konekt** : communautés avec fil de publications (texte, photos, vidéos, fichiers, GIF ; 60 Mo max. par fichier, 6 par publication), commentaires, « j'aime ». Les vidéos ne sont téléchargées qu'au clic. Code d'invitation `KON1-…`. Un **bouton d'appel** vidéo ou vocal est dans l'en-tête.
- **Appels** (Konekt) : détection de la **caméra** et du **micro** branchés (liste des périphériques, jauge du micro, aperçu), au choix « Vidéo et voix » ou « Voix seulement (micro) », couper le micro / la caméra, raccrocher. 6 personnes au maximum. Si la caméra est absente ou refusée, on peut rejoindre avec le micro seul, ou seulement écouter. **Sur téléphone** : image allégée (données mobiles), annulation d'écho et réduction du bruit activées.
- **Appels en 4G/5G (serveur TURN)** : les réseaux mobiles bloquent souvent les appels directs ; un serveur TURN relaie alors la voix et l'image (toujours chiffrées de bout en bout par WebRTC). Deux façons de l'activer, au choix : **(1)** dans votre relais Cloudflare : *Cloudflare → Realtime → TURN Server → Create* (offre gratuite, 1 000 Go/mois), puis, dans votre Worker, ajoutez les secrets `TURN_KEY_ID` (identifiant de la clé) et `TURN_KEY_API_TOKEN` (jeton de la clé), puis déployez le nouveau `worker.js` : l'application récupère les serveurs via `/turn` (aucun secret n'est dans le site) ; **(2)** ou saisissez votre propre serveur TURN (adresse, nom, mot de passe) dans la salle d'attente de l'appel → « Réglage TURN (réseau mobile) ». La salle d'attente indique si le relais est actif.
- **GIF (fenêtre de recherche)** : bouton « GIF » → tendances et recherche, vignettes à cliquer pour envoyer. Il faut **une clé GIPHY gratuite et personnelle**, créée une seule fois (l'API Tenor de Google a fermé le 30 juin 2026) : l'application l'explique à la première ouverture (developers.giphy.com → compte gratuit → « Create an App » → copier l'« API Key » → la coller). La clé est enregistrée dans votre **profil chiffré** (donc sauvegardée dans votre cloud avec le reste) ; elle n'est jamais dans le code du site. GIPHY voit les recherches faites depuis votre navigateur ; le GIF choisi est envoyé comme simple adresse giphy.com (les destinataires le chargent depuis GIPHY). Offre gratuite limitée en nombre de requêtes.
- **Liens vidéo et musique dans les messages** : un lien YouTube, Dailymotion, Vimeo, Rutube, Youku, Bilibili, Twitch, TikTok, Odysee, Niconico, Spotify, SoundCloud, Deezer, Apple Music, Bandcamp, Mixcloud, Tidal… devient une **carte cliquable** (miniature pour YouTube et Dailymotion) qui s'ouvre dans un **nouvel onglet**. Rien n'est lu dans l'application : seul le lien est ouvert.
- **Bouton « Vidéo / musique en ligne »** (Tchat et Konekt) : à côté des emojis et des GIF. Une petite fenêtre propose (1) de **coller un lien** (YouTube, Dailymotion, SoundCloud, Spotify, Vimeo… : le fournisseur est reconnu et affiché, un lien inconnu reste un simple lien) avec « Aussi dans Playlist Medias » pour le garder, et (2) de **choisir dans votre Playlist Medias** (onglets Vidéos / Musique, recherche, jusqu'à 4 médias cochés, bouton « Ouvrir Playlist Medias »). Le titre et le lien sont ajoutés au texte en cours ; à l'envoi ou à la publication, ils deviennent des cartes cliquables. Rien n'est téléchargé : seul le lien est ouvert.
- **Enregistrer la webcam et le micro (Tchat)** : bouton caméra dans l'en-tête de la conversation. Au choix « Vidéo et voix » ou « Voix seulement », choix du micro et de la caméra, jauge du micro, pause, découpage en plusieurs fichiers, et **destination = le cloud WebDAV de votre choix** (réglage mémorisé dans le profil, donc sauvegardé avec lui ; sans cloud choisi, le fichier est téléchargé sur l'appareil). Format **MP4** quand le navigateur l'enregistre (Chrome, Edge, Safari ; l'audio y est en AAC ou en Opus selon le navigateur) ; Firefox enregistre en WebM et l'application le signale.
- **Effets vidéo (fonds, cadres, GIF)** : un seul moteur (`fx.js`) partagé par l'enregistreur du Tchat, la **caméra de Konekt** et les **appels vidéo Konekt**. Un grand **interrupteur « Effets vidéo »** (48 px de haut, accessible au doigt) ouvre une galerie à 4 onglets : **Fonds** (18 décors dessinés par le programme : nuit, coucher de soleil, aurore, océan, plage, forêt, montagne, ville, bureau, bibliothèque, studio, bokeh, étoiles, brique, unis…, deux **flous**, et **votre image** via « Mon image… »), **Cadres** (13 : blanc, Polaroïd, or, bois, néon rose/bleu, pellicule, cœurs, fleurs, fête, étoiles, vintage, rond, et **votre cadre PNG** transparent), **GIF** (GIPHY, appareil ou adresse ; autocollants déplaçables à la souris ou au doigt) et **Réglages** (détection *auto* / *fond uni (clic sur le mur)* / *capturer le fond vide*, sensibilité, bords adoucis, « Tout remettre à zéro »). Sur téléphone ou écran tactile, les galeries deviennent des bandes à faire glisser avec de grandes vignettes. Tout est traduit (16 langues) et s'adapte de 320 px à la TV.
- **Réglages des effets mémorisés** : le fond, le cadre, le mode de détection, la sensibilité, les bords et l'état de l'interrupteur sont enregistrés dans votre **profil chiffré** (donc dans la sauvegarde cloud et la récupération sur un autre PC). Votre image perso, votre cadre PNG et les GIF posés ne sont jamais enregistrés. **La clé GIPHY** (`D.chat.gk`) est demandée une seule fois, enregistrée dans le même profil et réutilisée par le Tchat, Konekt et les effets ; l'onglet GIF indique si elle est déjà enregistrée.
- **Photo et vidéo avec effets** : dans l'enregistreur, « Prendre une photo » (avec fond, cadre et GIF) en plus de la vidéo ; bouton **« Caméra »** dans la zone de publication de Konekt (photo ou vidéo jointe à la publication, ou envoyée au cloud dans le dossier choisi) et dans l'en-tête du Tchat (envoi dans la conversation).
- **Effets pendant un appel Konekt** : avant d'entrer (salle d'attente) puis pendant l'appel avec le bouton ✨ de la barre (tiroir adapté aux petits écrans, aperçu de ce que voient les autres). L'image est envoyée aux participants par `replaceTrack` : on active, change ou coupe les effets sans raccrocher. Désactivés en appel « voix seulement ».
- **Limites honnêtes des effets** : le fond est remplacé par **soustraction de fond / détection automatique du mur** (aucune IA, aucun modèle téléchargé, tout reste dans le navigateur) : c'est très bon sur un mur ou un rideau assez uni et des vêtements qui contrastent (≈ 90 % de recouvrement mesuré), moins sur un décor chargé ou des vêtements de la couleur du mur (≈ 20 %) ; dans ce cas, utilisez « fond uni » ou « capturer le fond vide ». L'onglet doit rester **visible** (le navigateur ralentit les onglets cachés). Testé en Chrome, avec une caméra simulée ; les téléphones réels, la 4G et la télécommande TV ne sont pas testés ici.
- **Croix de fermeture** (×) sur toutes les petites fenêtres : emojis, GIF, menu d'options, notifications avec bouton ; Échap ferme aussi la fenêtre active.
- **Chiffrement** : une clé AES-256-GCM par conversation / communauté, créée sur votre appareil et contenue **uniquement dans le code d'invitation** ; le cloud ne voit que des fichiers illisibles (noms de fichiers : horodatage et 6 caractères d'identifiant, sans nom d'utilisateur). Le code d'invitation **ne contient jamais** le mot de passe du cloud : chacun utilise son propre accès au même cloud (même compte, ou dossier partagé). Les clés sont gardées dans le profil chiffré de l'utilisateur.
- **Zone rouge** (bouton toujours visible dans chaque application) : effacer l'historique de la conversation / de la communauté **pour tout le monde**, effacer l'historique de toutes ses conversations / communautés, supprimer seulement ses propres publications (Konekt), quitter, ou tout oublier sur cet appareil. Chaque action demande une confirmation.
- **Écrans** : mêmes règles que les autres applications (TV petite et grande, 4K, tablette, téléphone, PC) : la liste des conversations devient un menu sur écran étroit, les boutons restent atteignables à la télécommande.
- **Limites honnêtes** : (1) les nouveaux messages / publications arrivent par relecture du cloud (toutes les 4 à 12 s fenêtre ouverte, 45 à 60 s en arrière-plan), ce n'est pas instantané. (2) Les appels sont **directs entre navigateurs (WebRTC)** : la signalisation passe par de petits fichiers chiffrés sur le cloud (quelques secondes pour s'établir) ; sans serveur relais (TURN, voir plus haut), un appel peut **échouer sur certains réseaux** (4G d'opérateur, pare-feu d'entreprise). Les serveurs STUN/TURN (Google, Cloudflare ou le vôtre) voient votre adresse IP, comme dans tout appel WebRTC, et les participants la voient aussi. Le fonctionnement sur de vrais téléphones et réseaux mobiles n'a pas pu être vérifié ici (tests avec navigateurs automatisés et faux serveur TURN). (3) Ces applications ont été testées avec des navigateurs automatisés et de fausses caméras ; l'essai sur de vrais téléphones, vraies caméras et télécommandes de TV reste à faire par vous. (4) Les administrateurs du cloud voient la taille et la date des fichiers, pas leur contenu.

- **Clic droit sur le bureau** : *Mes apps*, *Applications IA*, *Lecteurs WebDAV*, *Post-it*, *Tutoriel (PDF)*, ajouter une application, ajouter un lecteur WebDAV, *Relais…*, fond, réglages. Échap ou un clic ailleurs ferme le menu.

Seules les adresses http(s) sont acceptées. La page d'accueil propose vos raccourcis web. Un site s'affiche dans la fenêtre (simple `iframe` isolé) **seulement s'il l'autorise** ; sinon (Google, YouTube, GitHub, Wikipédia… ou adresse `http://`) un message propose **Ouvrir dans un onglet**, avec « Essayer quand même » et « Toujours dans un onglet » (mémorisé dans votre profil, comme pour les raccourcis). Des mots saisis dans la barre ouvrent une recherche DuckDuckGo dans un onglet (les moteurs refusent l'affichage intégré). Pas de favoris.
  **Limites honnêtes** : le navigateur ne peut ni lire le titre d'une page d'un autre site ni suivre les liens cliqués dans la page ; *Précédent / Suivant* parcourent donc les adresses ouvertes **depuis la barre, l'accueil ou un raccourci**, pas les liens suivis dans le site. Aucun historique ni cookie n'est enregistré par l'application.

Un navigateur ne peut pas savoir à l'avance si un site interdit l'affichage intégré (en-têtes `X-Frame-Options` / CSP illisibles) : la détection automatique est une heuristique (sites connus, sites déjà basculés en onglet, adresses `http://`). Ces sites s'ouvrent dans un onglet avec un bouton **Essayer dans le bureau** ; pour les autres, la fenêtre propose toujours *Ouvrir dans un onglet* et *Toujours dans un onglet*.

Le bouton **Caster** n'envoie rien : il affiche en une phrase le chemin à suivre (Chrome : menu ⋮ → « Caster… » → « Caster l'onglet » ; Edge : menu « … » → « Enregistrer et partager » → « Caster le média sur l'appareil »). Si Chrome déplace ce menu, le bouton **Chercher le tutoriel** ouvre une recherche Google (nouvel onglet) avec les mots-clés pour retrouver la marche à suivre à jour. Aucune donnée n'est envoyée à Google, sauf cette recherche lancée par vous.
- **Playlist Medias** (et musiques) : **deux onglets séparés, « Vidéos » et « Musique »**. Collez le lien d'une vidéo (YouTube, Dailymotion, Vimeo, Rutube, Youku, Bilibili, Twitch, TikTok, Odysee, Niconico… ou n'importe quel site) ou d'une musique (Spotify, SoundCloud, Deezer, Apple Music, YouTube Music, Bandcamp, Mixcloud, Tidal…) : le **fournisseur est reconnu** (puce sur la carte), le **type** (vidéo / musique) est choisi automatiquement (modifiable) et **l'image est cherchée automatiquement** dès que vous collez le lien (même si vous cliquez directement sur « Ajouter » : la recherche est attendue) : YouTube et Dailymotion (adresses d'image connues), Vimeo, SoundCloud, Spotify et Rutube (vignette fournie par le site, « oEmbed »), puis, pour n'importe quel autre lien, la balise `og:image` de la page. La lecture est directe, puis passe par le **relais** du site s'il est configuré ; beaucoup de sites interdisent la lecture directe depuis un navigateur (CORS), donc **sans relais la détection échoue souvent hors YouTube/Dailymotion** : l'application l'indique. Un fichier vidéo ou audio direct (.mp4, .mp3…) n'est jamais téléchargé pour y chercher une image. Bouton **« Détecter l'image du lien »** pour relancer la recherche. Si rien n'est trouvé : **« Capturer une zone d'un onglet… »** (ordinateur : Chrome, Edge, Firefox ; absent sur téléphone) : le navigateur demande **quel onglet partager** (mettez la vidéo sur l'image voulue avant), une image fixe en est tirée, puis **vous dessinez le cadre** sur cette image (souris ou doigt ; format 16:9 verrouillé par défaut, « Image entière » possible) ; seul le cadre devient la miniature, rien d'autre n'est enregistré ni envoyé. Limites : on ne peut pas dessiner directement dans l'autre onglet (le cadre se trace sur la capture) ; les contenus protégés (DRM : Netflix, certaines vidéos payantes) donnent une image noire, c'est le navigateur qui l'impose ; Firefox ne propose pas toujours le choix d'un onglet (fenêtre ou écran) ; sinon choisissez une image ou « Image depuis une adresse… ». Les anciennes entrées restent dans « Vidéos ». Tout est dans votre profil chiffré, donc **sauvegardé dans votre cloud** (miniatures comprises). Fonctions communes : gardez les **liens directs** de vos vidéos avec leur **miniature**. Un clic sur la photo ouvre le lien dans un **nouvel onglet**. Catégorie choisie à l'ajout (modifiable, y compris en lot), **barre de recherche** (titre, catégorie, site ; sans tenir compte des accents ni des majuscules ; plusieurs mots), filtre par catégorie, tri, sélection multiple, suppression à tout moment (lien **et** miniature, avec confirmation). Capacité : **5 000 vidéos**, affichage par pages de 48 (« Afficher plus ») pour rester fluide. La miniature se choisit (fichier, glisser-déposer, Ctrl+V, adresse d'image) ; pour un lien YouTube elle est récupérée automatiquement si le navigateur y parvient. **Stockage** : liens et titres dans votre profil chiffré ; miniatures dans le navigateur (IndexedDB), par utilisateur, **non chiffrées**, incluses dans la sauvegarde cloud (*Sauvegarder maintenant*). Pas d'export de fichier : la playlist, les miniatures et les raccourcis voyagent par votre cloud. La suppression d'un compte efface ses miniatures.
- **Tutoriel (PDF)** : le bouton **Tutoriel** de la barre des tâches (et le clic droit sur le bureau) affiche **votre** PDF dans une nouvelle fenêtre. Au premier clic vous choisissez le fichier ; il est enregistré **non chiffré** dans ce navigateur, pour votre compte (inclus dans la sauvegarde de votre cloud ; absent du dépôt public). Pour le mettre à jour : **Réglages → Tutoriel (PDF) → Choisir / remplacer le PDF…**, ou **Retirer**. 80 Mo maximum.

Onglets *Boutique* / *Installées*, filtres par catégorie, recherche. Modifier une app du catalogue met aussi à jour sa copie installée. Le catalogue est propre à chaque utilisateur (clé `vd2.s.<id>`), sauvegardé, exporté et synchronisé avec le profil. L'ouverture des apps installées (`launch`) est inchangée.

Il s'affiche sur l'écran de connexion, dans la barre des tâches et dans « Mon compte » (où on peut le changer : *Changer mon avatar*). Plus de 1 400 textes sont traduits dans les 16 langues : barre des tâches, menu Démarrer, **description de chaque application intégrée**, boutons et titres de l'App Store, des stockages WebDAV, des lecteurs (musique, vidéo, documents, images), des sauvegardes, du compte et de la clé d'accès, des post-it, de la TV, de la radio, de l'enregistreur, du clavier virtuel, de la boîte à outils (calculs, unités, travaux, dates…), de l'éditeur, de l'atelier photo et d'OpenSubtitles ; les noms des 40 langues de sous-titres les plus courantes sont aussi traduits. Les phrases construites en assemblant des morceaux, les noms et descriptions des applications (catalogue, App Store, Mes apps, menu Démarrer, bureau : jamais traduits) et les longs textes d'aide restent en français. Pour corriger ou compléter une traduction : une ligne de `I18N_ROWS` dans `i18n.js` (le texte français sert de clé ; colonnes dans l'ordre de `I18N_LANGS`).

## Clavier virtuel
Application interne « Clavier virtuel » + bouton ⌨ dans la barre des tâches. Il écrit dans le champ sélectionné de n'importe quelle app interne, dans les 16 langues du profil : AZERTY / QWERTY / QWERTZ, russe, mongol, arabe, hindi, japonais (kana, ゛ ゜, katakana) et chinois (pinyin, caractères courants). Pour un site externe affiché dans un cadre, le navigateur interdit d'y écrire à la place de l'utilisateur : écrivez dans la **zone de saisie** du clavier, **Copier**, puis collez (Ctrl+V) dans le site. Fenêtre ancrée en bas, au premier plan, utilisable à la souris, au doigt et à la télécommande (flèches + OK).

### Texte prédictif
Pendant la frappe, une barre propose 3 mots (smartphone) ou 5 mots : d'abord **vos mots appris** (les plus utilisés en premier), puis une liste de **mots courants** de la langue du clavier (140 à 300 mots par langue, écrits à la main ; japonais : lecture → écriture, par exemple わた → 私 ; chinois : mots en caractères). Les accents sont ignorés pour chercher (« ete » propose « été ») et la majuscule tapée est reprise.
- **Apprentissage** : uniquement ce qui est écrit avec le clavier virtuel, au moment où un mot est terminé (espace, Entrée, ponctuation) ou choisi dans la barre. **Jamais** dans un champ de mot de passe, nombre, e-mail, téléphone, code ou carte. Les mots tout en majuscules ne sont pas appris.
- **Stockage** : chiffré (AES-GCM) avec la clé du profil dans le navigateur (`vd2.kw.<id>`). Si un cloud WebDAV est choisi pour la sauvegarde, une copie chiffrée `sormick-<id>.mots.json` est rangée dans le dossier « sormick-cloud » (fichier séparé de la sauvegarde du profil) ; les listes de vos appareils sont **fusionnées** (mots réunis, compteurs les plus élevés gardés). Rien n'est envoyé à un serveur de ce site. Le fichier n'est pas dans l'export des profils.
- **Réglages** dans la fenêtre du clavier : « Suggestions : oui / non » et « Oublier mes mots » (efface sur l'appareil et dans le cloud). Plafond : 3 000 mots (les moins utilisés sont oubliés en premier). Un changement de mot de passe rechiffre la liste.
- Limites : pas de prédiction du mot suivant, pas de correction automatique, pas de conversion en kanji.

## Code PIN (écrans de TV uniquement)
Sur un écran TV, « Mon compte » propose **Activer le code PIN (TV)** : 6 chiffres + nombre d'erreurs avant blocage (3, 4 ou 5). **Rien n'est proposé automatiquement** : le PIN n'existe que si vous l'activez vous-même, juste après vous être connecté sur cette TV. L'écran de connexion affiche alors un pavé numérique utilisable à la télécommande. Après le nombre d'erreurs choisi, le code PIN est bloqué ; le mot de passe reste toujours valable, et après l'avoir saisi l'écran propose de **recréer le code PIN**.
- **Stockage chiffré** : le PIN protège une copie du mot de passe (PBKDF2 + AES-GCM). Cette copie, le nombre d'erreurs et le seuil sont de plus chiffrés par une **clé d'appareil non exportable** (IndexedDB, elle ne quitte jamais la TV) : recopier le stockage du navigateur sur un autre appareil ne sert à rien. Si les données de la TV sont effacées, le PIN devient illisible et il suffit de saisir le mot de passe puis de le recréer. Si le navigateur n'offre pas ce stockage sécurisé, le PIN est refusé.
- Il n'est ni exporté ni sauvegardé, et un code à 6 chiffres reste moins solide qu'un mot de passe (à réserver à une TV maîtrisée). Il n'est jamais proposé sur PC, tablette ni smartphone.

## Type d'écran
L'écran (TV, ordinateur, tablette, smartphone) est reconnu automatiquement (navigateur de TV, boîtier Android sans écran tactile, très grand écran sans tactile…). Si la détection se trompe, **Réglages → Type d'écran** (et le sélecteur de l'écran de connexion) permet de le forcer ; le bloc **Informations sur cet écran** donne les mesures et la raison de la détection (bouton Copier).

**Adaptation à la taille** : sur TV, l'interface est mise à l'échelle selon la largeur *et* la hauteur de l'écran (de 960×540 à 4K) ; si la barre des tâches manque de place, elle se compacte automatiquement par étapes (nom d'utilisateur, libellés, texte « Démarrer », puis horloge) pour que tous les boutons restent visibles. Le bouton **Plein écran** est dans la barre des tâches. Le choix est mémorisé sur cet appareil.

## Curseur de télécommande (TV uniquement)
Sur un écran TV, le curseur s'active **avec n'importe quelle télécommande** : **OK maintenu 1 seconde**, ou une **touche couleur** (rouge, verte, jaune, bleue), **Info**, **Menu** ou **\***/**#** ; le bouton **Souris** (en bas à droite de l'écran de connexion, taille adaptée à la TV) et le bouton **curseur** de la barre des tâches font la même chose. Une astuce s'affiche quelques fois au début. Ensuite : **flèches** = déplacer (le pointeur accélère et fait défiler la page au bord de l'écran), **OK** = cliquer, **OK maintenu + flèches** = glisser, **Retour** = quitter. Sur un champ de texte, le curseur se range et le clavier virtuel prend le relais.

## Taille à l'écran (TV, tous appareils)
Chaque fenêtre calcule son propre zoom pour que l'application garde assez de place (jamais plus grand que le zoom de la barre des tâches, réduit si l'écran logique de la TV est petit). Les sites web ouverts dans le bureau (apps du cloud, navigateur) sont affichés à leur taille normale, sans zoom. L'écran de connexion avec le code PIN tient toujours en entier (pavé à droite sur un écran bas) et le clavier virtuel reste entièrement visible. Le menu Démarrer est un peu plus petit que la barre des tâches sur TV, et à la télécommande les flèches parcourent toutes ses applications (jusqu'en bas), puis retournent à la recherche avec « Haut».

**Relais et adresse « www. »** : le worker accepte le site avec ou sans `www.` (par exemple `monsite.fr` et `www.monsite.fr`). Avant, une TV ouvrant la version en `www.` était refusée par le relais et affichait « Connexion impossible ». Il faut recoller la dernière version de `worker.js` dans Cloudflare. Remarque : le profil est enregistré par adresse de site, donc une adresse en `www.` et une sans `www.` ont chacune leurs propres profils.

## Caster (TV, Radio, lecteurs Vidéo et Musique)

**Chrome / Edge sur ordinateur** : le bouton utilise d'abord le **kit officiel Google Cast** (script chargé à la demande depuis `www.gstatic.com`, application de réception standard de Google, rien à installer sur la télévision), car l'API du navigateur ne voit pas toujours les Chromecast que le menu « Caster… » de Chrome affiche. Pendant la diffusion, le lecteur local continue **sans son** : ses boutons (lecture/pause, volume, barre de position) pilotent la télévision et restent exacts (la télévision ou le téléphone qui la commande le remettent aussi à jour) ; un 2e clic sur « Caster » arrête la diffusion. Si le kit ne se charge pas, l'API du navigateur prend le relais. **Non testé avec un vrai Chromecast** (seul un kit simulé a servi aux tests).
Le bouton **Caster** utilise l'API « Remote Playback » du navigateur (Chrome, Edge, Safari ; pas Firefox) : la télévision va chercher elle-même le flux, puis les commandes du lecteur la pilotent.
- **Chaînes TV et radios** : l'adresse du flux est envoyée telle quelle (un flux protégé ou sans autorisation peut être refusé par la télévision).
- **Fichiers de votre cloud** : la télévision ne peut pas envoyer de mot de passe. Le **relais Cloudflare** fabrique donc un **lien temporaire chiffré** pour ce seul fichier (6 h par défaut, 12 h maximum). **Il faut recoller la dernière version de `worker.js` dans Cloudflare et définir le secret `RELAY_TOKEN`.** Limite à connaître : **toute personne qui possède ce lien peut lire ce fichier** jusqu'à son expiration ; le mot de passe du cloud n'est jamais dans le lien.
- **Fichiers de cet appareil** : impossible (la télévision ne peut pas lire votre disque) ; l'application propose de caster l'onglet entier ou de mettre le fichier dans le cloud.
- Sans API de diffusion (Firefox, navigateur de TV), l'aide « caster l'onglet » s'affiche. Non testé avec un vrai Chromecast / AirPlay : seuls l'API simulée et le relais l'ont été.

## Applications intégrées et « À propos » traduits
Les noms et descriptions des applications intégrées, leurs icônes (bureau, menu Démarrer, Mes apps, recherche) et la fenêtre « À propos » suivent la langue du profil (16 langues, tout est dans `i18n.js`). Les applications que vous ajoutez ou celles du catalogue gardent leur nom d'origine. Les textes composés (« « X » est installée… », compteurs, adresses, messages d'erreur…) sont écrits sous forme de modèles avec `{0}`, `{1}` dans `i18n.js` : `tr()` reconnaît aussi ces phrases quand un nom ou un nombre y est inséré. Restent dans leur forme d'origine : les noms de langues très rares des listes TV, les libellés des guides EPG des fournisseurs et les noms/descriptions des applications cloud.

## Favoris du lecteur vidéo
Onglet **Favoris** : le **cœur** met de côté la vidéo en cours (vidéos du **cloud** uniquement : un fichier de l'appareil n'a pas d'adresse durable). L'onglet a sa **barre de recherche**, un bouton « Tout lire » et la pochette du film quand elle existe. Favoris conservés dans le profil et la sauvegarde cloud.

## Cover des films (lecteur vidéo)
À l'ouverture d'une vidéo, le titre déduit du nom du fichier est cherché sur **IMDb** (service de suggestions public, sans clé ni réglage) pour identifier le film, puis son **affiche française** est cherchée dans le catalogue Apple TV / iTunes Store France (même année, titre proche) ; à défaut, l'affiche d'IMDb (souvent l'originale) est associée à ce fichier ; elle s'affiche en grand à droite du lecteur (à part : elle n'est jamais intégrée à la vidéo et n'empêche pas sa lecture). Si l'affiche ne correspond pas : **Changer le cover…** → saisissez le titre (en français) → **Choisir** (les affiches françaises sont listées en premier). Seul le titre cherché est envoyé à imdb.com et à apple.com (recherche publique) ; seule l'**adresse** de l'image est conservée (profil chiffré). Les images restent la propriété d'IMDb et sont affichées depuis leurs serveurs. Ce service n'est pas une API officielle : s'il change ou refuse l'accès, le lecteur fonctionne normalement, sans cover.

## Sormick Radio
Radios du monde : **Découvrir** interroge en direct l'annuaire communautaire **Radio Browser** (radio-browser.info) avec des filtres **langue / genre / pays** modifiables à volonté et une recherche par nom ; seules les radios en https sont affichées (un site https ne peut pas lire un flux http). **Mes radios** : vos propres adresses de flux (ajout, modification, suppression), classées par langue et genre de votre choix (*Renommer langue / genre* change une catégorie pour toutes les radios). **Paroles** : le panneau « Paroles de la chanson » affiche les paroles du morceau en cours, cherchées sur **LRCLIB** (lrclib.net, base libre et gratuite, sans clé). Le titre en cours est lu dans le flux de la radio (métadonnées ICY) quand le serveur de la radio l'autorise depuis un site web (cas d'Icecast) ; sinon, saisissez « Artiste – Titre » et cliquez *Chercher les paroles*. Seul ce texte est envoyé à LRCLIB. Les radios de l'annuaire se modifient aussi directement (crayon à côté de l'étoile : nom, adresse, langue, genre, pays) : la version modifiée est enregistrée dans *Mes radios* et remplace l'originale ; la supprimer de *Mes radios* rétablit l'originale, import / export (JSON, M3U, PLS), quelques radios d'exemple. **Enregistrer** : le flux est copié par morceaux (un seul fichier ou un fichier toutes les 5 à 60 minutes) vers le **stockage WebDAV et le dossier de votre choix** (ou téléchargé sur l'appareil). Si la radio n'autorise pas la lecture depuis un site web (CORS), l'enregistrement passe par le **relais**. Le flux est gardé en mémoire jusqu'à l'envoi du morceau : fermer la fenêtre arrête et envoie.

**Favoris** (onglet à part) : touchez le **cœur** d'une radio (dans « Découvrir » ou « Mes radios ») ; l'onglet **Favoris** a sa propre **barre de recherche** (sans tenir compte des accents ni des majuscules) et ses filtres langue / genre. Les favoris sont dans votre profil chiffré et dans la sauvegarde cloud.

**Débit / qualité** : le bouton **Débit** (radio en cours) liste les autres flux de la même radio dans l'annuaire avec leur débit (32, 64, 128, 320 kbit/s…), permet de saisir une autre adresse de flux et de **garder** le choix dans « Mes radios ». Limite assumée : un flux radio en direct ne peut pas être ré-encodé par le navigateur, on change donc de débit en choisissant un autre flux réel de la radio.

**Mettre à jour** fonctionne même si vos listes sont vides : dans « Découvrir », il propose alors les radios récentes qui correspondent aux filtres choisis (langue, genre, pays), sinon les nouveautés générales de l'annuaire. **Mettre à jour** (dans « Mes radios ») : contrôle vos radios auprès de l'annuaire (jusqu'à 400 par passage), propose de **retirer** celles qui ont disparu ou ne répondent plus, **rafraîchit** les adresses qui ont changé et propose les **nouveautés** de l'annuaire (selon les filtres de « Découvrir », sinon les langues de vos radios). Une fenêtre de revue s'affiche d'abord : rien n'est modifié avant « Appliquer », tout est décochable. Vos propres radios inconnues de l'annuaire ne sont jamais retirées.

**Mettre à jour** et **Sources…** sont aussi dans « Découvrir » et « Favoris ». **Sources…** : modifiez les **serveurs de l'annuaire Radio Browser** (interrogés dans l'ordre ; ajout, modification, suppression, « Tester », « Adresses d'origine » : utile si l'annuaire change un jour d'adresse) et ajoutez vos **propres listes de radios** (M3U, PLS ou JSON, https) lues à chaque mise à jour : les radios retirées de leur liste sont proposées à la suppression, les nouvelles à l'ajout. **Nouvelle source** : dès l'enregistrement, l'application propose « Importer maintenant ? » et lit uniquement cette source ; **toutes** ses radios sont proposées (cochées, avec « Tout cocher / Tout décocher », 500 par passage, le reste à la mise à jour suivante), rien n'est ajouté avant « Appliquer ». **Anti-doublons** : une radio est ignorée si son adresse est déjà présente (http/https, majuscules, « / » final, « www. » et « #… » ne comptent pas) ou si son nom est le même (accents, casse, « (128k) », « [Geo-blocked] », « HD »… ignorés ; deux radios de même nom mais de pays différents ne sont pas des doublons). Ce contrôle s'applique aux mises à jour, à l'import de fichier, aux exemples et à l'ajout manuel (adresse) ; le nombre de doublons ignorés est indiqué.

**Titre en cours, paroles, pochette** : le titre est lu dans les métadonnées ICY du flux (si le serveur de la radio l'autorise). Il est **nettoyé** (numéro de piste, « (Official Video) », « feat. … », année) et essayé **dans les deux sens** (Artiste – Titre / Titre – Artiste, certaines radios inversent) ; les résultats LRCLIB sont **classés par ressemblance** (accents et ponctuation ignorés) et le meilleur est affiché en premier (♫ = paroles synchronisées). Quand les paroles sont synchronisées, la **ligne chantée est mise en valeur** et défile : le suivi démarre au changement de titre (décalage réglable −1 s / +1 s) ; pour un morceau déjà commencé à la connexion, cliquez sur la ligne chantée pour caler le suivi. La **pochette de l'album** (ou la photo de l'artiste à défaut) s'affiche **à droite des paroles**, et en miniature à côté du titre quand le panneau est fermé.

## Sormick TV (IPTV / M3U)
**Catalogue** : les listes M3U publiques du projet **iptv-org** (github.com/iptv-org/iptv, licence CC0) classées par **langue**, **catégorie** ou **pays**, chargées à la demande. **Mes listes** : vos propres adresses M3U (nom, adresse, langue ; modifiables) et ouverture d'un fichier `.m3u` de l'appareil. **Mes chaînes** : favoris modifiables. Les chaînes des listes se modifient aussi directement (crayon à côté de l'étoile) : la version modifiée est enregistrée dans *Mes chaînes* et remplace l'originale ; la supprimer rétablit l'originale. **Sous-titres** : si la liste HLS d'une chaîne annonce des pistes de sous-titres (WebVTT), elles sont téléchargées par le site et affichées automatiquement (langue de l'interface en priorité), avec un choix de piste et un décalage ±0,5 s pour les directs. **Guide des programmes (EPG)** : fichier XMLTV (.xml ou .xml.gz, 60 Mo max.) saisi dans le panneau « Guide des programmes » (enregistré dans votre profil chiffré) ou annoncé par la liste M3U (`url-tvg`) ; il affiche le programme en cours et les suivants de la chaîne choisie (rapprochement par `tvg-id`, ou par nom). Lecture HLS native du navigateur (Chrome, Edge, Safari) ; les chaînes en http sont masquées (bloquées par le navigateur) ; beaucoup de flux publics sont instables ou protégés. **Enregistrer** : copie du flux HLS (ou direct) par morceaux vers votre WebDAV (qualité basse / moyenne / haute pour les chaînes multi-qualités) ; fichiers `.ts` / `.mp4` à lire avec VLC. Les flux chiffrés (AES-128) ne peuvent pas être enregistrés. Les flux sans CORS passent par le relais (consomme son quota).

**Recherche dans « Mes chaînes »** (vos favoris IPTV) : barre de recherche (nom, genre, langue, sans accents ni majuscules) en plus du filtre par genre. **Mettre à jour** : relit vos listes de « Mes listes », propose de retirer les chaînes **disparues de leur liste d'origine** et d'ajouter les **chaînes nouvelles** (la première lecture d'une liste du catalogue ou de « Mes listes » sert de référence ; les nouveautés sont proposées aux mises à jour suivantes). Une **source que vous ajoutez** dans « Sources… » est traitée autrement : « Importer maintenant ? » est proposé et **toutes** ses chaînes sont présentées (cochées, 500 par passage, le reste à la mise à jour suivante). **Anti-doublons** : une chaîne est ignorée si son adresse est déjà dans « Mes chaînes » (http/https, majuscules, « / » final… ignorés) ou si son nom est identique (accents, casse, « (720p) », « HD », « [Geo-blocked] » ignorés) ; les doublons ignorés sont comptés dans le message. Fenêtre de revue avant toute modification ; les chaînes ajoutées à la main ne sont jamais retirées.

**Mettre à jour** est aussi dans l'onglet **Catalogue** (il lit la liste affichée). **Sources…** : modifiez l'**adresse du catalogue** (par défaut `https://iptv-org.github.io/iptv/`, bouton « Tester » ; si vous la changez, vos listes, favoris et références suivent) et ajoutez vos **propres sources M3U** lues à chaque mise à jour, en plus de « Mes listes » et des listes d'origine de vos chaînes. Le catalogue enregistre la liste ouverte comme référence dès son chargement.

**Guide des programmes (EPG)** : sur chaque chaîne, « ▶ programme en cours » s'affiche dès que le guide du pays est chargé (automatiquement à l'ouverture d'une liste par pays ou par langue ; le guide annoncé par la liste elle-même est aussi utilisé). Format **XMLTV** (`.xml` ou `.xml.gz`, 60 Mo max décompressé). La correspondance se fait par identifiant `tvg-id` puis par nom de chaîne (accents, « HD », « FR »… ignorés). Sources du catalogue : **EPGShare** (epgshare01.online, un guide par pays) et **epg.pw**. Le bouton **Guides par pays…** ouvre le catalogue, **entièrement modifiable** (modifier l'adresse d'un guide, en ajouter, en retirer, tester, *Rétablir le catalogue d'origine*, importer un catalogue JSON distant `[{"name":"…","cc":"fr","url":"https://…xml.gz"}]` pour le mettre à jour sans toucher au code). Un guide « manuel » peut aussi être saisi dans le panneau EPG. Aucune donnée personnelle n'est envoyée.

## Kaléido (atelier photo et dessin)
Remplace l'ancienne application « Dessin » (même emplacement d'enregistrement : *Enregistrer dans…*). Tout est écrit à la main, sans bibliothèque externe, et tourne dans le navigateur.
- **Dessin** : pinceau, crayon, marqueur (calligraphie), aérographe, gomme, pot de peinture, dégradés (linéaire, radial, angulaire, réfléchi ; arc-en-ciel, coucher de soleil, océan, feu), formes (rectangle, arrondi, ellipse, ligne, flèche, triangle, étoile, hexagone, cœur), texte (polices, gras, italique, contour, sur un nouveau calque), autocollants, pipette, **lissage**, **symétrie et mandalas** (miroirs, rotations ×3 à ×12), sensibilité au stylet.
- **Retouche photo** : tampon de duplication (Alt + clic), correcteur de taches, doigt, flou et netteté locaux, éclaircir / assombrir, éponge, mosaïque locale (flouter un visage), yeux rouges, recadrage (proportions), rotation / retournement, taille de l'image et de la zone de travail ; **réglages** (luminosité / contraste, exposition, ombres / hautes lumières, saturation, teinte, température, niveaux, postérisation, seuil, bichromie, auto-niveaux, auto-contraste, balance des blancs) et **filtres** (flou gaussien, netteté, réduction du bruit, grain, vignette, pixelliser, relief, contours, croquis, dessin animé, vagues, tourbillon, loupe, kaléidoscope) avec **aperçu en direct**, bouton *Comparer*, et 17 **filtres rapides** avec aperçus (noir et blanc, sépia, vintage, dramatique, pop-art…). *Avant / après* compare avec l'image telle qu'à l'ouverture.
- **Calques** (40 max) : opacité, 16 modes de fusion, ordre, duplication, fusion, aplatissement ; **sélections** (rectangle, ellipse, lasso, baguette magique ; ajouter / retirer / intersection, bords adoucis, inverser, agrandir / réduire) ; copier / couper / coller (Ctrl+V d'une image), annuler / rétablir (40 étapes, plafonné en mémoire), histogramme.
- **Fichiers** : ouverture depuis l'appareil, le cloud WebDAV, par glisser-déposer ou collage ; export **PNG, JPEG, WebP, GIF, BMP, ICO** (encodeurs écrits à la main), **PDF** (une page A4) ou **projet à calques `.kaleido`** (une archive ZIP de calques PNG + `meta.json`, relue avec validation de taille et de format) ; envoi sur le WebDAV ou téléchargement. Images importées réduites à 3200 px (côté le plus long), 4096 px au maximum pour une image créée. Une confirmation évite de fermer la fenêtre avec des modifications non enregistrées.

## Éditeur de texte, impression et PDF
- **Listes** : puces, numérotation, **listes à plusieurs niveaux** (1. / 1.1. / 1.1.1., Tab / Maj+Tab) et **listes à cocher** (courses…).
- **Formats** : ouverture **et** enregistrement en **TXT, Markdown, HTML, RTF, Word (.docx), OpenDocument (.odt)** et **PDF** ; le contenu d'un fichier existant se modifie puis s'enregistre au même endroit. TXT garde le texte et les listes (`- `, `1. `, ☐ / ☑, retrait) mais pas le gras ni les couleurs ; les autres formats gardent la mise en forme. Limites honnêtes : import docx / odt / rtf sans images, tableaux aplatis ; import PDF = texte seulement.
- **Imprimer** (éditeur, lecteur de documents, Kaléido) : fenêtre d'impression du navigateur (texte vectoriel ; « Enregistrer au format PDF » possible). **Enregistrer en PDF** : sur l'appareil ou dans le WebDAV de votre choix ; le PDF est fabriqué sans bibliothèque (le texte y est une image, non sélectionnable : pour un PDF au texte sélectionnable, utilisez Imprimer → Enregistrer au format PDF).

## Post-it
Le bouton **Post-it** ouvre une fenêtre défilante : on peut en créer beaucoup (300 max) sans encombrer le bureau. Chacun a une couleur et peut être **épinglé sur le bureau** (5 au maximum, déplaçables à la souris ou au clavier, **redimensionnables** avec la poignée en bas à droite, souris ou flèches du clavier ; la taille est enregistrée) ; « détacher » le remet simplement dans la liste. Les post-it sont par utilisateur et **chiffrés** avec le profil.

## Contact
Dans *À propos*, « Contactez-moi. » ouvre simplement votre **application de messagerie** avec un nouvel e-mail adressé au contact : aucun service tiers, aucun formulaire, aucune configuration. L'adresse n'est jamais affichée dans l'interface ; elle n'est présente que **brouillée** dans `config.js` (voir « Ce que contient le dépôt public »).

## Ce que contient le dépôt public (et ce qu'il ne contient pas)
- **Aucun mot de passe, jeton, clé ni donnée d'utilisateur** : tout ce qui est secret (identifiants WebDAV, clé OpenSubtitles, notes, playlists) reste dans le navigateur de chaque utilisateur, chiffré avec son mot de passe.
- `config.js` ne contient **plus** l'adresse du relais (champ vide) ni aucun jeton : ils se saisissent dans l'application et vivent dans le profil chiffré. Il ne reste que l'adresse de contact, **brouillée** (inversion + base64) : c'est de l'**obfuscation, pas du chiffrement** (le navigateur doit pouvoir la lire) ; elle évite seulement l'aspiration automatique d'adresses e-mail.
- Les connexions WebDAV (adresse, utilisateur, mot de passe, icône) sont saisies dans l'application, jamais dans le code.
- Quelqu'un qui télécharge le dépôt obtient l'application, pas vos données : sans le mot de passe d'un profil, un profil exporté ou le stockage du navigateur est illisible (AES-256-GCM).
- Avant de publier : vérifiez que `.gitignore` est bien envoyé et ne mettez jamais de mot de passe, de jeton Cloudflare ou de fichier de profil exporté dans le dépôt.

## Passerelle facultative
```bash
npm install
PROXY_TOKEN="$(openssl rand -hex 24)" ALLOWED_ORIGIN="https://<utilisateur>.github.io" npm start
```
À placer derrière HTTPS, puis : *Réglages → Passerelle* (adresse + jeton, chiffrés dans votre profil). Variables : `PORT`, `ALLOW_PRIVATE_HOSTS` (ex. `nas.local`).
Elle ajoute : WebDAV sans CORS (mais sans lecture en continu), et affichage dans le bureau de certains sites qui interdisent l'intégration (relais, avec des limites : seuls les clics sur liens sont réécrits).

## Sécurité du code
CSP stricte (pas de script inline ; seule exception : le script officiel Google Cast de `www.gstatic.com`, chargé uniquement quand vous cliquez sur « Caster » dans Chrome/Edge sur ordinateur — pour le retirer, supprimez `https://www.gstatic.com` de `script-src` dans `index.html`), aucune donnée externe injectée via `innerHTML` (le HTML de l'éditeur passe par une liste blanche), adresses limitées à http(s), iframes en `sandbox`, fichiers lus en blob avec type MIME imposé, enregistrements chiffrés avec un nouvel IV à chaque écriture et authentifiés (toute modification du fichier est détectée), ralentissement après échecs de connexion.

## Contributions externes : qu'est-ce qui reste à risque ?
Avec ce fonctionnement, quelqu'un qui consulte ou copie le dépôt public n'y trouve **ni adresse de relais, ni jeton, ni identifiant WebDAV** ; son propre déploiement (autre adresse de site) a de toute façon un stockage de navigateur séparé du vôtre, et votre relais refuse les sites autres que le vôtre (et, avec le jeton, toute requête sans jeton). Pour tester une fonction, un contributeur saisit **ses propres** informations de connexion dans **son** copie de l'application.
Le risque qui demeure est le **code que vous publiez vous-même** : une modification malveillante fusionnée dans votre site s'exécuterait dans votre navigateur et pourrait lire vos données déchiffrées (identifiants, jeton) pendant votre session. Donc : relisez chaque proposition de modification avant de la fusionner, activez la protection de la branche `main` (GitHub → Settings → Branches : « Require a pull request before merging »), ne donnez pas d'accès en écriture au dépôt, et utilisez des mots de passe d'application révocables chez vos fournisseurs WebDAV.

## Le relais peut-il afficher dans le bureau un site qui interdit l'intégration ?
**Non, pas de façon fiable, et ce n'est volontairement pas fait.** Un site qui refuse l'affichage dans une fenêtre (en-têtes `X-Frame-Options` / `frame-ancestors`) le fait pour se protéger. Un relais pourrait retirer ces en-têtes, mais la page chargée ainsi ne fonctionnerait pas : connexion (cookies tiers), scripts et appels réseau y échouent presque toujours (Google, YouTube, GitHub, réseaux sociaux, la plupart des assistants IA). Cela transformerait aussi votre relais en proxy web généraliste. Solution retenue : ces sites s'ouvrent dans un **onglet** (mode automatique, ou « Toujours dans un onglet »). La passerelle facultative auto-hébergée (`server.js`, Réglages) tente un affichage réécrit avec les mêmes limites ; elle est inutile pour WebDAV puisque le relais Cloudflare existe.

Pour éviter de saisir le chemin, **glissez dans la fenêtre le raccourci Windows (.lnk) du programme** (bureau ou menu Démarrer de Windows) : le chemin complet est lu dans le fichier, dans le navigateur, sans rien envoyer. Un `.exe` glissé directement ne donne que son nom (un navigateur ne révèle jamais le chemin complet d'un fichier) ; astuce : Maj + clic droit → « Copier en tant que chemin ».
