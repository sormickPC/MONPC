# sormick Cloud — PC virtuel

Un mini Windows dans le navigateur : bureau, barre des tâches, App Store, stockages WebDAV, lecteurs intégrés (musique, vidéo + sous-titres, documents Office/PDF/TXT, images), éditeur de texte enrichi, plusieurs utilisateurs.
Le site fonctionne **sur GitHub Pages**. Services externes : le **relais Cloudflare** (à vous, pour joindre les WebDAV sans CORS) et, facultatif, OpenSubtitles pour les sous-titres. **SFTP n'est pas pris en charge** : un navigateur ne sait pas parler SFTP ; utilisez WebDAV.

## Publier
Settings → Pages → *Deploy from a branch* → `main` / `/ (root)`. Le site s'ouvre sur `https://<utilisateur>.github.io/<dépôt>/` (pas sur la page du dépôt).

## Utilisateurs et confidentialité (dépôt public)
- Le dépôt ne contient **que du code** : aucune donnée personnelle.
- Chaque utilisateur a son bureau, ses raccourcis de bureau, son fond, ses connexions WebDAV, ses playlists et ses documents. Le **catalogue de l'App Store est propre à chaque utilisateur**.
- Les données d'un utilisateur sont **chiffrées dans le navigateur** (AES-256-GCM). La clé est dérivée de son mot de passe (PBKDF2-SHA256, 600 000 itérations, sel aléatoire) et n'existe qu'en mémoire pendant la session. Les mots de passe WebDAV et OpenSubtitles sont dans ce profil chiffré : une fois enregistrés, ils ne sont plus redemandés.
- Sont stockés **en clair** sur l'appareil, par utilisateur : le **catalogue de l'App Store** (noms, adresses, descriptions), l'**avatar**, les **miniatures de la playlist** et le **PDF du tutoriel**, ainsi que la liste des noms d'utilisateurs. Les liens et titres de la playlist, le fond d'écran personnalisé, les connexions, les Post-it… restent dans le profil chiffré. Ne mettez rien de confidentiel dans une description d'application, une miniature ou le PDF.
- Le mot de passe d'un utilisateur **ne peut pas être récupéré** (il n'existe aucun serveur). En cas d'oubli, le profil est perdu.
- Les données restent **dans le navigateur de cet appareil** (le site demande au navigateur de ne pas les effacer). Pour les retrouver sur un autre ordinateur, deux moyens :
  - **Sauvegarde dans votre cloud WebDAV** (recommandé) : *Mon compte → Sauvegarde dans mon cloud* : choisissez un de vos lecteurs, puis *Sauvegarder maintenant* (ou cochez la sauvegarde automatique : 1 minute après une modification et au verrouillage). Un dossier `sormick-cloud` est créé : `sormick-<id>.profil.json` (profil **chiffré** + catalogue, nom et avatar en clair) et `sormick-<id>.media.json` (miniatures et PDF en clair). Sur le nouvel ordinateur : écran de connexion → **Restaurer depuis mon cloud** (adresse, utilisateur et mot de passe du cloud, relais si besoin), puis connexion avec le mot de passe du profil. Le fond d'écran personnalisé, la playlist, les connexions, les Post-it suivent. **La dernière sauvegarde remplace la précédente** (pas de fusion entre deux ordinateurs). Le fichier du profil reste inutilisable sans votre mot de passe ; le reste est lisible par quiconque accède à ce dossier du cloud.
  - **Fichier de connexion chiffré** (*Mon compte → Sauvegarde dans mon cloud → Exporter mon fichier de connexion*) : un fichier `sormick-connexion.txt` contenant l'adresse, l'utilisateur et le mot de passe du cloud (et l'adresse + jeton du relais) **chiffrés** (PBKDF2 600 000 itérations + AES-GCM) par une phrase secrète de 8 caractères minimum choisie à l'export. Sur l'écran de connexion : **Charger un fichier de connexion** → phrase secrète → les profils sauvegardés sont cherchés sans rien retaper. À refaire après un changement de lecteur de sauvegarde. Format texte (et non PDF : un PDF ne se relit pas de façon fiable). La phrase secrète n'est pas récupérable ; le fichier donne accès au cloud, pas au profil (protégé par son propre mot de passe).
  - **Profil léger** (*Mon compte → Exporter mon profil léger (chiffré)*) : un seul fichier `.profil-leger.json`, **entièrement chiffré** par le mot de passe du profil, qui contient déjà la connexion au cloud, le relais et le jeton, la playlist (liens), le fond d'écran, les Post-it. Sur le nouvel ordinateur : **Importer un profil** (proposé aussi sur le tout premier écran) → mot de passe du profil → l'application propose de **récupérer raccourcis, miniatures de playlist et PDF du tutoriel dans le cloud déjà connecté**. Tant que ce n'est pas fait (ou ignoré), les sauvegardes sont suspendues pour ne pas écraser celles du cloud. Récupération manuelle possible à tout moment : *Mon compte → Sauvegarde dans mon cloud → Récupérer mes raccourcis et miniatures depuis le cloud* (fusion sans doublon).
  - **Mes données** (*Mon compte → Exporter mes données / Importer mes données*) : **un seul bouton** pour exporter ou importer ensemble les raccourcis (App Store), la playlist (liens, catégories, miniatures) et le PDF du tutoriel, dans `sormick-donnees.json` (en clair, sans le profil ni les connexions). Import : fusion sans doublon ; les anciens exports `sormick-playlist` et `sormick-raccourcis` sont toujours acceptés. Le profil garde ses boutons à part (complet ou léger).
  - **Fichier** : *Mon compte → Exporter mon profil complet* (profil chiffré + catalogue, miniatures et PDF **en clair**, fichier parfois volumineux), puis *Importer un profil* sur l'écran de connexion.
- Verrouillage automatique après inactivité (réglable). Sur un ordinateur partagé, verrouillez la session ou videz les données du site.
- Limite honnête : ce n'est pas une protection contre quelqu'un qui contrôle déjà votre navigateur ou votre ordinateur ; choisissez un mot de passe long.

## WebDAV : adresse + utilisateur + mot de passe
Dans *Stockage cloud*, trois champs suffisent : l'adresse du serveur, l'utilisateur, le mot de passe. L'application teste la connexion, l'enregistre (chiffrée) et ouvre l'explorateur ; vous ne la ressaisissez plus jamais. Le nom est déduit de l'adresse (modifiable dans *Options*), `https://` est ajouté si vous l'oubliez.
- **Aucun réglage CORS, aucun bouton à cliquer** : l'application essaie d'abord en direct ; si le navigateur refuse, elle **bascule toute seule par le relais** (voir ci-dessous) et s'en souvient pour cette connexion (lecture en continu et envoi de fichiers compris). L'adresse et le jeton du relais se saisissent **une fois** dans l'application (*Stockages cloud → Relais…* ou clic droit sur le bureau → *Relais…*), jamais dans le dépôt.
- **Site du fournisseur et icône** (*Options*, facultatif) : l'adresse du site officiel de votre cloud. L'**icône** du fournisseur est détectée automatiquement (comme pour les apps : `favicon.ico` du site, puis service d'icônes DuckDuckGo si activé) ; sinon importez la vôtre (*Importer une icône…*). Elle remplace le nuage par défaut sur la carte du stockage, l'accès rapide et le raccourci du bureau. Chaque explorateur et chaque lecteur (musique, vidéo, documents, images, sélecteur cloud) a alors un bouton **Mon cloud (site officiel)** qui l'ouvre dans un nouvel onglet. Seules les adresses `https://` sont acceptées.
- **Explorateur** : cases à cocher, **Supprimer** (un ou plusieurs fichiers/dossiers, avec confirmation explicite ; un dossier est supprimé avec son contenu), **Déplacer…** et **Copier…** (choix du dossier de destination dans une fenêtre ; jamais d'écrasement : un élément du même nom est refusé ; un dossier ne peut pas être placé dans lui-même ; WebDAV `MOVE`/`COPY`), **Nouveau dossier**, **Nouveau texte**, **Téléverser ici**, **Raccourci bureau** (icône du stockage sur le bureau). Un clic ouvre le fichier dans le bon lecteur ; si aucun lecteur ne le prend en charge, l'application **demande avant de le télécharger** (rien n'est téléchargé sans accord). Pas de miniatures : la navigation reste rapide. **Recherche** : une barre en haut cherche par nom (insensible aux majuscules et aux accents, plusieurs mots possibles) soit dans le **dossier actuel** (filtre instantané), soit dans **tout le lecteur** (parcours des dossiers, 3 à la fois, bouton *Arrêter*, limites de 500 résultats et 3 000 dossiers ; chaque résultat indique son dossier, un clic l'ouvre, le bouton *Dossier* y emmène). Sur un gros lecteur, la recherche globale peut être longue et utilise beaucoup de requêtes (donc du quota du relais si vous l'utilisez). Les boutons « Fichier local » et « Lire le dossier » n'existent que dans les lecteurs concernés.
- Les stockages ne s'ouvrent jamais dans un nouvel onglet ; SFTP n'est pas pris en charge (voir plus bas).
- Diagnostic en cas d'échec : *serveur injoignable* (adresse, réseau, certificat), *identifiants refusés (401)*, *dossier introuvable (404)*. Serveur sur **réseau local** (NAS) : le relais, situé dans le cloud, ne peut pas l'atteindre ; l'accès direct exige alors un réglage CORS côté serveur (origine `https://<utilisateur>.github.io` autorisée, méthodes `GET, PUT, DELETE, MKCOL, PROPFIND, OPTIONS`, en-têtes `Authorization, Depth, Range`).

## Relais : se connecter à un WebDAV tiers sans réglage serveur
Si vous ne contrôlez pas le serveur WebDAV (fournisseur cloud, entreprise, hébergeur), il ne peut pas recevoir le réglage CORS. Solution : un **relais** à vous, déployé **une seule fois** (`worker.js`), qui fait les requêtes à la place du navigateur.

**Mise en place (≈ 5 minutes, offre gratuite de Cloudflare)**
1. Compte gratuit sur [cloudflare.com](https://dash.cloudflare.com/sign-up).
2. *Workers & Pages* → *Create* → *Create Worker* → nom au choix → *Deploy*.
3. *Edit code* : tout remplacer par le contenu de `worker.js`, vérifier `const SITE = 'https://…github.io'` (sans `/` final), *Deploy*.
4. **Verrouiller par jeton (recommandé)** : dans l'application, *Stockages cloud → Relais…* → *Générer un jeton* → *Copier le jeton*. Dans Cloudflare : *Settings → Variables and Secrets → Add* → type **Secret**, nom **`RELAY_TOKEN`**, valeur = le jeton → *Deploy*.
5. Dans l'application (même fenêtre *Relais*) : collez l'adresse du Worker (`https://…workers.dev`) et le jeton → *Tester* (« Relais joignable et verrouillé ») → *Enregistrer*. L'adresse et le jeton sont enregistrés **chiffrés dans votre profil** ; `config.js` reste vide (`RELAY_URL = ''`).

**Ce que le relais fait et ne fait pas**
- Sans le secret `RELAY_TOKEN`, il n'exige rien de plus que le contrôle du site d'origine ; **avec** le secret, toute requête sans le bon jeton (en-tête `X-Relay-Token`, comparaison à durée constante) est refusée : connaître l'adresse du relais ne suffit plus. Le bouton *Tester* signale si le relais est resté ouvert.
- Il ne répond qu'aux pages de votre site (en-tête `Origin`) et ne relaie que des adresses **https:// publiques** (pas d'IP, pas de `localhost`, pas de réseau privé). Redirections revérifiées, l'identifiant n'est jamais envoyé à un autre hôte. Le jeton n'est pas transmis au serveur WebDAV.
- Il ne stocke ni ne journalise rien dans son code ; l'en-tête d'identification est transmis tel quel au serveur WebDAV.
- **Limites, dites honnêtement** : vos identifiants et vos fichiers **transitent pour le relais** (en HTTPS jusqu'à lui et depuis lui) : il appartient à votre compte Cloudflare, mais il faut lui faire confiance. Le jeton est stocké dans votre profil chiffré et envoyé avec chaque requête ; si quelqu'un contrôle déjà votre navigateur ou du code exécuté dans votre session, il peut le lire (voir « Contributions externes »). Changez-le en cas de doute (nouveau secret dans Cloudflare + *Relais…*).
- Certains hébergeurs bloquent les adresses de Cloudflare : la connexion échoue alors même avec le relais. Un site peut aussi limiter les échecs de mot de passe : utilisez un mot de passe d'application si le fournisseur en propose.

## Pourquoi pas SFTP ?
SFTP est un protocole SSH, pas une requête web : **aucun navigateur ne peut l'ouvrir**. Il a donc été retiré. Si vos fichiers sont derrière SFTP, exposez le même dossier en WebDAV (SFTPGo propose les deux ; ou `rclone serve webdav monsftp:/ --addr :8443 --user NOM --pass MOTDEPASSE --allow-origin https://<utilisateur>.github.io --cert cert.pem --key cle.pem`, à vérifier avec `rclone serve webdav --help`).

## Applications intégrées (non supprimables)
Toujours présentes dans **Mes apps** (jamais dans l'App Store, qui ne liste que les raccourcis web) : **Lecteur de musique**, **Lecteur vidéo**, **Lecteur de documents**, **Visionneuse d'images**, **Stockage cloud**, **Éditeur de texte**, **Playlist vidéos**, **Post-it**. On peut seulement les retirer du bureau puis les y remettre. Chaque lecteur ouvre un fichier **depuis l'appareil** (bouton « Fichier local ») ou **depuis un stockage WebDAV** (bouton « Depuis le cloud… », navigation, sélection multiple). « Lire le dossier » n'existe que dans le lecteur de musique/vidéo/images.
- **Musique** : liste de lecture, **Vider la liste**, lecture en continu. **Pochette** et **paroles** intégrées au MP3 (étiquettes ID3v2.2/2.3/2.4 : titre, artiste, album, image APIC, paroles USLT) : la pochette s'affiche en grand dans le lecteur et le bouton **Paroles** ouvre une nouvelle fenêtre qui suit le titre en cours. Pour un fichier WebDAV, seul le début du fichier est lu (lecture partielle). **MP3 uniquement** (pas FLAC/M4A) ; sans paroles intégrées, l'application l'indique. Aucun service de paroles externe n'est interrogé.
- **Vidéo** : lecture en continu avec déplacement dans la vidéo ; sous-titres `.srt`, `.vtt`, `.ass` chargés à la main, détectés automatiquement s'ils portent le même nom dans le même dossier, décalables de ±0,5 s ; recherche **OpenSubtitles** (compte et clé API gratuits, à saisir dans la fenêtre ; stockés chiffrés dans votre profil). L'accès direct à leur API dépend de leur réglage CORS : **non vérifié** depuis mon environnement (testé avec une API simulée). S'il est refusé, l'application le dit et vous pouvez charger le fichier à la main.
- **Documents** : `.docx`, `.xlsx`, `.pptx`, `.odt/.ods/.odp`, `.txt`, `.md`, `.csv`, `.json`, `.pdf` (PDF.js, mot de passe PDF géré). Affichage simplifié ; anciens formats `.doc/.xls/.ppt/.rtf` à télécharger. Documents convertis sans `innerHTML` ; XML avec DOCTYPE/ENTITY refusé ; limites de taille.
- **Images** : zoom, déplacement, rotation, plein écran, diaporama, glisser-déposer, flèches du clavier.

**Lecture en continu sans proxy** : `sw.js` (service worker de votre propre site) récupère le fichier WebDAV directement, avec vos identifiants gardés **en mémoire seulement**, par morceaux (Range). Si le serveur n'expose pas `Content-Range`, repli automatique sur un téléchargement complet.

## Barre des tâches, bureau, applications web
- **Barre des tâches** : *App Store* (catalogue de raccourcis web), **Mes apps** (vos raccourcis web en haut, les applications intégrées en bas), **IA**, **Lecteurs WebDAV**, **Tutoriel**, **Post-it**, fond d'écran, réglages, à propos, **Plein écran**.
- **Lecteurs WebDAV** : fenêtre d'accès rapide listant les stockages connectés (icône du fournisseur, ouverture directe, site du fournisseur, raccourci bureau) avec un bouton **Ajouter un lecteur WebDAV**.
- **Fenêtres ouvertes en grand** : l'explorateur WebDAV, *Mes apps*, l'*App Store*, la fenêtre *IA* et les applications web ouvertes dans le bureau s'ouvrent agrandies en **vrai plein écran** (la fenêtre couvre tout l'écran ; la barre des tâches reste visible et cliquable par-dessus, le contenu s'arrête juste au-dessus d'elle) (bouton « Agrandir » pour revenir à la taille normale). Les lecteurs et les autres applications intégrées gardent leur taille normale.
- **Mes apps** : vos raccourcis web (par catégorie) en haut, puis les applications intégrées en bas ; contient les applications intégrées (non supprimables, avec raccourci bureau) ; elles ne sont **pas** dans l'App Store, qui ne liste que le catalogue de raccourcis web.
- **Plein écran** : le bouton de la barre met le bureau en plein écran ; **Échap** (géré par le navigateur) revient à la normale, comme un second clic sur le bouton.
- **Clic droit sur le bureau** : *Mes apps*, *Applications IA*, *Lecteurs WebDAV*, *Post-it*, *Tutoriel (PDF)*, ajouter une application, ajouter un lecteur WebDAV, *Relais…*, fond, réglages. Échap ou un clic ailleurs ferme le menu.
- **Raccourcis du bureau** : chaque application, chaque stockage WebDAV, chaque raccourci web peut être posé sur le bureau ou retiré.
- **Applications IA** : dans l'App Store, choisissez *Type : application IA*. Elle apparaît alors dans la fenêtre du bouton **IA** (et pas dans *Mes apps*). Mêmes modes d'ouverture que les autres apps.
- **Mode d'ouverture** de chaque app web : **automatique** (par défaut), **toujours dans le bureau** ou **toujours dans un onglet**. Un navigateur ne peut pas savoir à l'avance si un site interdit l'affichage intégré (en-têtes `X-Frame-Options` / CSP illisibles) : la détection automatique est une heuristique (sites connus, sites déjà basculés en onglet, adresses `http://`). Ces sites s'ouvrent dans un onglet avec un bouton **Essayer dans le bureau** ; pour les autres, la fenêtre propose toujours *Ouvrir dans un onglet* et *Toujours dans un onglet*.
- Icônes : détectées depuis le site (`/favicon.ico`, puis le service d'icônes DuckDuckGo, désactivable dans Réglages) ou importées par vous.

- **Caster** (lecteurs musique et vidéo) : un site web ne peut pas ouvrir lui-même la fenêtre de diffusion du navigateur. Le bouton **Caster** n'envoie rien : il affiche en une phrase le chemin à suivre (Chrome : menu ⋮ → « Caster… » → « Caster l'onglet » ; Edge : menu « … » → « Enregistrer et partager » → « Caster le média sur l'appareil »). Si Chrome déplace ce menu, le bouton **Chercher le tutoriel** ouvre une recherche Google (nouvel onglet) avec les mots-clés pour retrouver la marche à suivre à jour. Aucune donnée n'est envoyée à Google, sauf cette recherche lancée par vous.
- **Playlist vidéos** : gardez les **liens directs** de vos vidéos (n'importe quel fournisseur) avec leur **miniature**. Un clic sur la photo ouvre le lien dans un **nouvel onglet**. Catégorie choisie à l'ajout (modifiable, y compris en lot), **barre de recherche** (titre, catégorie, site ; sans tenir compte des accents ni des majuscules ; plusieurs mots), filtre par catégorie, tri, sélection multiple, suppression à tout moment (lien **et** miniature, avec confirmation). Capacité : **5 000 vidéos**, affichage par pages de 48 (« Afficher plus ») pour rester fluide. La miniature se choisit (fichier, glisser-déposer, Ctrl+V, adresse d'image) ; pour un lien YouTube elle est récupérée automatiquement si le navigateur y parvient. **Stockage** : liens et titres dans votre profil chiffré ; miniatures dans le navigateur (IndexedDB), par utilisateur, **non chiffrées**, incluses dans la sauvegarde cloud et dans « Exporter mon profil ». **Exporter / Importer** : depuis *Mon compte → Exporter mes données / Importer mes données* (un seul fichier pour raccourcis + playlist + miniatures + PDF, en clair, à garder en lieu sûr). La suppression d'un compte efface ses miniatures.
- **Tutoriel (PDF)** : le bouton **Tutoriel** de la barre des tâches (et le clic droit sur le bureau) affiche **votre** PDF dans une nouvelle fenêtre. Au premier clic vous choisissez le fichier ; il est enregistré **non chiffré** dans ce navigateur, pour votre compte (inclus dans la sauvegarde cloud et l'export ; absent du dépôt public). Pour le mettre à jour : **Réglages → Tutoriel (PDF) → Choisir / remplacer le PDF…**, ou **Retirer**. 80 Mo maximum.
- **App Store** : fenêtre à part (violet/orange, logo « App Store Sormick » en tête, **ouverte agrandie**) pour la distinguer de la liste « Mes apps ».

- **Logo et icône d'onglet** : le logo sormick Cloud est affiché en grand dans **À propos** (sur une pastille blanche, lisible quel que soit le thème) ; `favicon.png` est l'icône de l'onglet du navigateur. Le titre de l'onglet reste « sormick Cloud — PC virtuel ».
- **Avatar** : à la création d'un utilisateur, on choisit un avatar (12 emojis, l'initiale du nom, ou **sa propre photo**, recadrée au centre et réduite à 96×96 px). Il s'affiche sur l'écran de connexion, dans la barre des tâches et dans « Mon compte » (où on peut le changer : *Changer mon avatar*). Il est enregistré **avec la liste des profils, donc non chiffré** (il doit être visible avant la saisie du mot de passe) : n'y mettez rien de sensible. Il suit l'export / import du profil.

## Post-it
Le bouton **Post-it** ouvre une fenêtre défilante : on peut en créer beaucoup (300 max) sans encombrer le bureau. Chacun a une couleur et peut être **épinglé sur le bureau** (5 au maximum, déplaçables à la souris ou au clavier, **redimensionnables** avec la poignée en bas à droite, souris ou flèches du clavier ; la taille est enregistrée) ; « détacher » le remet simplement dans la liste. Les post-it sont par utilisateur et **chiffrés** avec le profil.

## Contact
Dans *À propos*, « Contactez-moi. » ouvre simplement votre **application de messagerie** avec un nouvel e-mail adressé au contact : aucun service tiers, aucun formulaire, aucune configuration. L'adresse n'est jamais affichée dans l'interface ; elle n'est présente que **brouillée** dans `config.js` (voir « Ce que contient le dépôt public »).

## Ce que contient le dépôt public (et ce qu'il ne contient pas)
- **Aucun mot de passe, jeton, clé ni donnée d'utilisateur** : tout ce qui est secret (identifiants WebDAV, clé OpenSubtitles, notes, playlists) reste dans le navigateur de chaque utilisateur, chiffré avec son mot de passe.
- `config.js` ne contient **plus** l'adresse du relais (champ vide) ni aucun jeton : ils se saisissent dans l'application et vivent dans le profil chiffré. Il ne reste que l'adresse de contact, **brouillée** (inversion + base64) : c'est de l'**obfuscation, pas du chiffrement** (le navigateur doit pouvoir la lire) ; elle évite seulement l'aspiration automatique d'adresses e-mail.
- Les connexions WebDAV (adresse, utilisateur, mot de passe, icône) sont saisies dans l'application, jamais dans le code.
- Quelqu'un qui télécharge le dépôt obtient l'application, pas vos données : sans le mot de passe d'un profil, un profil exporté ou le stockage du navigateur est illisible (AES-256-GCM).
- Avant de publier : vérifiez que `.gitignore` est bien envoyé et ne mettez jamais de mot de passe, de jeton Cloudflare ou de fichier de profil exporté dans le dépôt.

```bash
npm install
PROXY_TOKEN="$(openssl rand -hex 24)" ALLOWED_ORIGIN="https://<utilisateur>.github.io" npm start
```
À placer derrière HTTPS, puis : *Réglages → Passerelle* (adresse + jeton, chiffrés dans votre profil). Variables : `PORT`, `ALLOW_PRIVATE_HOSTS` (ex. `nas.local`).
Elle ajoute : WebDAV sans CORS (mais sans lecture en continu), et affichage dans le bureau de certains sites qui interdisent l'intégration (relais, avec des limites : seuls les clics sur liens sont réécrits).

## Sécurité du code
CSP stricte (pas de script inline), aucune donnée externe injectée via `innerHTML` (le HTML de l'éditeur passe par une liste blanche), adresses limitées à http(s), iframes en `sandbox`, fichiers lus en blob avec type MIME imposé, enregistrements chiffrés avec un nouvel IV à chaque écriture et authentifiés (toute modification du fichier est détectée), ralentissement après échecs de connexion.

## Contributions externes : qu'est-ce qui reste à risque ?
Avec ce fonctionnement, quelqu'un qui consulte ou copie le dépôt public n'y trouve **ni adresse de relais, ni jeton, ni identifiant WebDAV** ; son propre déploiement (autre adresse de site) a de toute façon un stockage de navigateur séparé du vôtre, et votre relais refuse les sites autres que le vôtre (et, avec le jeton, toute requête sans jeton). Pour tester une fonction, un contributeur saisit **ses propres** informations de connexion dans **son** copie de l'application.
Le risque qui demeure est le **code que vous publiez vous-même** : une modification malveillante fusionnée dans votre site s'exécuterait dans votre navigateur et pourrait lire vos données déchiffrées (identifiants, jeton) pendant votre session. Donc : relisez chaque proposition de modification avant de la fusionner, activez la protection de la branche `main` (GitHub → Settings → Branches : « Require a pull request before merging »), ne donnez pas d'accès en écriture au dépôt, et utilisez des mots de passe d'application révocables chez vos fournisseurs WebDAV.

## Le relais peut-il afficher dans le bureau un site qui interdit l'intégration ?
**Non, pas de façon fiable, et ce n'est volontairement pas fait.** Un site qui refuse l'affichage dans une fenêtre (en-têtes `X-Frame-Options` / `frame-ancestors`) le fait pour se protéger. Un relais pourrait retirer ces en-têtes, mais la page chargée ainsi ne fonctionnerait pas : connexion (cookies tiers), scripts et appels réseau y échouent presque toujours (Google, YouTube, GitHub, réseaux sociaux, la plupart des assistants IA). Cela transformerait aussi votre relais en proxy web généraliste. Solution retenue : ces sites s'ouvrent dans un **onglet** (mode automatique, ou « Toujours dans un onglet »). La passerelle facultative auto-hébergée (`server.js`, Réglages) tente un affichage réécrit avec les mêmes limites ; elle est inutile pour WebDAV puisque le relais Cloudflare existe.
