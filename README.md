# sormick Cloud — PC virtuel

Un mini Windows dans le navigateur : bureau, barre des tâches, App Store, stockages WebDAV, lecteurs intégrés (musique, vidéo + sous-titres, documents Office/PDF/TXT, images), éditeur de texte enrichi, plusieurs utilisateurs.
Le site fonctionne **sur GitHub Pages**. Services externes : le **relais Cloudflare** (à vous, pour joindre les WebDAV sans CORS) et, facultatif, OpenSubtitles pour les sous-titres. **SFTP n'est pas pris en charge** : un navigateur ne sait pas parler SFTP ; utilisez WebDAV.

## Publier
Settings → Pages → *Deploy from a branch* → `main` / `/ (root)`. Le site s'ouvre sur `https://<utilisateur>.github.io/<dépôt>/` (pas sur la page du dépôt).

## Utilisateurs et confidentialité (dépôt public)
- Le dépôt ne contient **que du code** : aucune donnée personnelle.
- Chaque utilisateur a son bureau, ses raccourcis de bureau, son fond, ses connexions WebDAV, ses playlists et ses documents. Le **catalogue de l'App Store est propre à chaque utilisateur**.
- Les données d'un utilisateur sont **chiffrées dans le navigateur** (AES-256-GCM). La clé est dérivée de son mot de passe (PBKDF2-SHA256, 600 000 itérations, sel aléatoire) et n'existe qu'en mémoire pendant la session. Les mots de passe WebDAV et OpenSubtitles sont dans ce profil chiffré : une fois enregistrés, ils ne sont plus redemandés.
- Sont stockés **en clair** sur l'appareil, par utilisateur : le **catalogue de l'App Store** (noms, adresses, descriptions), l'**avatar**, les **miniatures de la playlist** et le **PDF du tutoriel**, ainsi que la liste des noms d'utilisateurs. Les liens et titres de la playlist, le fond d'écran personnalisé, les connexions, les Post-it… restent dans le profil chiffré. Ne mettez rien de confidentiel dans une description d'application, une miniature ou le PDF.
- Le mot de passe d'un utilisateur **ne peut pas être récupéré** (il n'existe aucun serveur). En cas d'oubli, le profil est perdu.
- Les données restent **dans le navigateur de cet appareil** (le site demande au navigateur de ne pas les effacer). Pour les retrouver sur un autre ordinateur, deux moyens :
  - **Sauvegarde dans votre cloud WebDAV** (recommandé) : *Mon compte → Sauvegarde dans mon cloud* : choisissez un de vos lecteurs, puis *Sauvegarder maintenant* (ou cochez la sauvegarde automatique : 1 minute après une modification et au verrouillage). Un dossier `sormick-cloud` est créé : `sormick-<id>.profil.json` (profil **chiffré** + catalogue, nom et avatar en clair) et `sormick-<id>.media.json` (miniatures et PDF en clair). Un bouton **Sauvegarder maintenant dans mon cloud** est toujours visible dans *Mon compte*, et **au verrouillage** (bouton « Verrouiller / changer d'utilisateur ») l'application propose de sauvegarder si des données ont changé depuis la dernière sauvegarde (« Sauvegarder et verrouiller » / « Verrouiller sans sauvegarder » / « Annuler » ; pas de question si la sauvegarde automatique est cochée ni pour le verrouillage par inactivité). Sur le nouvel ordinateur : écran de connexion → **Restaurer depuis mon cloud** (adresse, utilisateur et mot de passe du cloud, relais si besoin), puis connexion avec le mot de passe du profil. Le fond d'écran personnalisé, la playlist, les connexions, les Post-it, la clé API et le compte OpenSubtitles suivent (tout cela est dans le profil chiffré). **La dernière sauvegarde remplace la précédente** (pas de fusion entre deux ordinateurs). Le fichier du profil reste inutilisable sans votre mot de passe ; le reste est lisible par quiconque accède à ce dossier du cloud.
  - **Export des profils (seul export vers l'ordinateur)** (*Mon compte → Exporter tous mes profils (chiffrés)*) : un fichier `sormick-profils.json` contenant **tous les profils de l'appareil** avec leurs connexions cloud (mots de passe WebDAV), relais et jetons. Chaque profil (avec ses clouds, relais, jetons et la clé API / le compte OpenSubtitles) reste chiffré par son mot de passe, et l'ensemble est **chiffré une seconde fois par un « mot de passe d'export »** (8 caractères minimum, choisi à l'export, PBKDF2 600 000 itérations + AES-GCM, non récupérable) **redemandé à l'import**. Sur le nouvel ordinateur : **Importer un profil** (écran de connexion ou tout premier écran) → mot de passe d'export → chaque profil se déverrouille avec son propre mot de passe → l'application propose de **récupérer raccourcis, playlist (miniatures) et PDF du tutoriel dans le cloud déjà connecté** de ce profil. Tant que ce n'est pas fait (ou ignoré), les sauvegardes de ce profil sont suspendues pour ne pas écraser celles du cloud. Récupération manuelle à tout moment : *Mon compte → Sauvegarde dans mon cloud → Récupérer mes données depuis le cloud*. Cette récupération **fusionne sans rien supprimer** : elle ajoute les raccourcis, miniatures et PDF, mais aussi ce qui est plus récent dans la sauvegarde que dans le fichier de profils importé (**post-it**, liens de la playlist, playlists musique, documents, clouds, relais, clé OpenSubtitles) ; un post-it présent des deux côtés garde la version la plus récente, et un réglage unique (fond d'écran, relais déjà saisi) n'est pas écrasé. Si le mot de passe du profil a changé depuis la sauvegarde, il est redemandé. **Tout le reste passe par le cloud** : aucun export de raccourcis, playlist, miniatures ni PDF vers l'ordinateur. Les anciens fichiers d'un seul profil restent importables.
- Verrouillage automatique après inactivité (réglable), ou **immédiat avec le raccourci clavier Alt + L** (sans question ; la sauvegarde automatique, si elle est cochée, est faite avant). Sur un ordinateur partagé, verrouillez la session ou videz les données du site.
- Limite honnête : ce n'est pas une protection contre quelqu'un qui contrôle déjà votre navigateur ou votre ordinateur ; choisissez un mot de passe long.

## WebDAV : adresse + utilisateur + mot de passe
**Diagnostic** : le bouton *Diagnostic* (cartes des lecteurs, et dans un dossier affiché vide) montre ce que le serveur répond réellement à la liste d'un dossier : adresse demandée, mode d'accès (direct ou relais), code HTTP, type de réponse, nombre d'entrées et leurs noms. Le mot de passe ou le jeton n'est jamais affiché (seulement sa longueur) ; le texte est copiable. Si le serveur répond autre chose que du WebDAV, une erreur claire s'affiche au lieu d'un dossier vide.

Dans *Stockage cloud*, trois champs suffisent : l'adresse du serveur, l'utilisateur, le mot de passe. L'application teste la connexion, l'enregistre (chiffrée) et ouvre l'explorateur ; vous ne la ressaisissez plus jamais. Le nom est déduit de l'adresse (modifiable dans *Options*), `https://` est ajouté si vous l'oubliez.
- **Aucun réglage CORS, aucun bouton à cliquer** : l'application essaie d'abord en direct ; si le navigateur refuse, elle **bascule toute seule par le relais** (voir ci-dessous) et s'en souvient pour cette connexion (lecture en continu et envoi de fichiers compris). L'adresse et le jeton du relais se saisissent **une fois** dans l'application (*Stockages cloud → Relais…* ou clic droit sur le bureau → *Relais…*), jamais dans le dépôt.
- **Site du fournisseur et icône** (*Options*, facultatif) : l'adresse du site officiel de votre cloud. L'**icône** du fournisseur est détectée automatiquement (comme pour les apps : `favicon.ico` du site, puis service d'icônes DuckDuckGo si activé) ; sinon importez la vôtre (*Importer une icône…*). Elle remplace le nuage par défaut sur la carte du stockage, l'accès rapide et le raccourci du bureau. Chaque explorateur et chaque lecteur (musique, vidéo, documents, images, sélecteur cloud) a alors un bouton **Mon cloud (site officiel)** qui l'ouvre dans un nouvel onglet. Seules les adresses `https://` sont acceptées.
- **Explorateur** : cases à cocher, **Supprimer** (un ou plusieurs fichiers/dossiers, avec confirmation explicite ; un dossier est supprimé avec son contenu), **Déplacer…** et **Copier…** (choix du dossier de destination dans une fenêtre ; jamais d'écrasement : un élément du même nom est refusé ; un dossier ne peut pas être placé dans lui-même ; WebDAV `MOVE`/`COPY`), **Nouveau dossier**, **Nouveau texte**, **Téléverser ici**, **Raccourci bureau** (icône du stockage sur le bureau). Un clic ouvre le fichier dans le bon lecteur ; si aucun lecteur ne le prend en charge, l'application **demande avant de le télécharger** (rien n'est téléchargé sans accord). Pas de miniatures : la navigation reste rapide. **Recherche** : une barre en haut cherche par nom (insensible aux majuscules et aux accents, plusieurs mots possibles) soit dans le **dossier actuel** (filtre instantané), soit dans **tout le lecteur** (parcours des dossiers, 3 à la fois, bouton *Arrêter*, limites de 500 résultats et 3 000 dossiers ; chaque résultat indique son dossier, un clic l'ouvre, le bouton *Dossier* y emmène). Sur un gros lecteur, la recherche globale peut être longue et utilise beaucoup de requêtes (donc du quota du relais si vous l'utilisez). Les boutons « Fichier local » et « Lire le dossier » n'existent que dans les lecteurs concernés.
- Les stockages ne s'ouvrent jamais dans un nouvel onglet ; SFTP n'est pas pris en charge (voir plus bas).
- Diagnostic en cas d'échec : *serveur injoignable* (adresse, réseau, certificat), *identifiants refusés (401)*, *dossier introuvable (404)*. Serveur sur **réseau local** (NAS) : le relais, situé dans le cloud, ne peut pas l'atteindre ; l'accès direct exige alors un réglage CORS côté serveur (origine `https://<utilisateur>.github.io` autorisée, méthodes `GET, PUT, DELETE, MKCOL, PROPFIND, OPTIONS`, en-têtes `Authorization, Depth, Range`).

## Relais : se connecter à un WebDAV tiers sans réglage serveur
Si vous ne contrôlez pas le serveur WebDAV (fournisseur cloud, entreprise, hébergeur), il ne peut pas recevoir le réglage CORS. Solution : un **relais** à vous, déployé **une seule fois** (`worker.js`), qui fait les requêtes à la place du navigateur.

**Mise en place (≈ 5 minutes, offre gratuite de Cloudflare)**
1. Compte gratuit sur [cloudflare.com](https://dash.cloudflare.com/sign-up).
2. *Workers & Pages* → *Create* → *Create Worker* → nom au choix → *Deploy*.
3. *Edit code* : tout remplacer par le contenu de `worker.js`, vérifier `const SITE = 'https://…github.io'` (sans `/` final), *Deploy*.
4. **Verrouiller par jeton (recommandé)** : dans l'application, *Stockages cloud → Relais…* → *Générer un jeton* → *Copier le jeton*. Dans Cloudflare : *Settings → Variables and Secrets → Add* → type **Secret**, nom **`RELAY_TOKEN`**, valeur = le jeton → *Deploy*.
5. Dans l'application (même fenêtre *Relais*) : collez l'adresse du Worker (`https://…workers.dev`) et le jeton → *Tester* (« Relais joignable et verrouillé ») → *Enregistrer*. L'adresse et le jeton sont enregistrés **chiffrés dans votre profil** ; `config.js` reste vide (`RELAY_URL = ''`).

**Ce que le relais fait et ne fait pas**
- Sans le secret `RELAY_TOKEN`, il n'exige rien de plus que le contrôle du site d'origine ; **avec** le secret, toute requête sans le bon jeton (en-tête `X-Relay-Token`, comparaison à durée constante) est refusée : connaître l'adresse du relais ne suffit plus. Le bouton *Tester* signale si le relais est resté ouvert.
- Il ne répond qu'aux pages de votre site (en-tête `Origin`) et ne relaie que des adresses **https:// publiques** (pas d'IP, pas de `localhost`, pas de réseau privé). Redirections revérifiées, l'identifiant n'est jamais envoyé à un autre hôte. Le jeton n'est pas transmis au serveur WebDAV.
- Il ne stocke ni ne journalise rien dans son code ; l'en-tête d'identification est transmis tel quel au serveur WebDAV.
- **Limites, dites honnêtement** : vos identifiants et vos fichiers **transitent pour le relais** (en HTTPS jusqu'à lui et depuis lui) : il appartient à votre compte Cloudflare, mais il faut lui faire confiance. Le jeton est stocké dans votre profil chiffré et envoyé avec chaque requête ; si quelqu'un contrôle déjà votre navigateur ou du code exécuté dans votre session, il peut le lire (voir « Contributions externes »). Changez-le en cas de doute (nouveau secret dans Cloudflare + *Relais…*).
- Certains hébergeurs bloquent les adresses de Cloudflare : la connexion échoue alors même avec le relais. Un site peut aussi limiter les échecs de mot de passe : utilisez un mot de passe d'application si le fournisseur en propose.

## Pourquoi pas SFTP ?
SFTP est un protocole SSH, pas une requête web : **aucun navigateur ne peut l'ouvrir**. Il a donc été retiré. Si vos fichiers sont derrière SFTP, exposez le même dossier en WebDAV (SFTPGo propose les deux ; ou `rclone serve webdav monsftp:/ --addr :8443 --user NOM --pass MOTDEPASSE --allow-origin https://<utilisateur>.github.io --cert cert.pem --key cle.pem`, à vérifier avec `rclone serve webdav --help`).

## Applications intégrées (non supprimables)
Toujours présentes dans **Mes apps** (jamais dans l'App Store, qui ne liste que les raccourcis web) : **Lecteur de musique**, **Lecteur vidéo**, **Lecteur de documents**, **Visionneuse d'images**, **Stockage cloud**, **Éditeur de texte**, **Playlist vidéos**, **Post-it**, **Sormick Radio**, **Sormick TV**, **Enregistreur d’écran**, **Dessin**. On peut seulement les retirer du bureau puis les y remettre. Chaque lecteur ouvre un fichier **depuis l'appareil** (bouton « Fichier local ») ou **depuis un stockage WebDAV** (bouton « Depuis le cloud… », navigation, sélection multiple). « Lire le dossier » n'existe que dans le lecteur de musique/vidéo/images.
- **Musique** : liste de lecture, **Vider la liste**, lecture en continu. **Pochette** et **paroles** intégrées au MP3 (étiquettes ID3v2.2/2.3/2.4 : titre, artiste, album, image APIC, paroles USLT) : la pochette s'affiche en grand dans le lecteur et le bouton **Paroles** ouvre une nouvelle fenêtre qui suit le titre en cours. Pour un fichier WebDAV, seul le début du fichier est lu (lecture partielle). **MP3 uniquement** (pas FLAC/M4A) ; sans paroles intégrées, l'application l'indique. Aucun service de paroles externe n'est interrogé.
- **Vidéo** : lecture en continu avec déplacement dans la vidéo ; sous-titres `.srt`, `.vtt`, `.ass` chargés à la main, détectés automatiquement s'ils portent le même nom dans le même dossier, décalables de ±0,5 s ; recherche **OpenSubtitles** dans **105 langues** (toutes celles de l'API : français, anglais, indonésien, mongol, tétoum / tetun dili, arabe, chinois simplifié / traditionnel / cantonais, etc. ; le français et les langues courantes sont en tête de liste) (compte et clé API gratuits, à saisir dans la fenêtre ; stockés chiffrés dans votre profil). L'accès direct à leur API dépend de leur réglage CORS : **non vérifié** depuis mon environnement (testé avec une API simulée). S'il est refusé, l'application le dit et vous pouvez charger le fichier à la main.
- **Documents** : `.docx`, `.xlsx`, `.pptx`, `.odt/.ods/.odp`, `.txt`, `.md`, `.csv`, `.json`, `.pdf` (PDF.js, mot de passe PDF géré). Affichage simplifié ; anciens formats `.doc/.xls/.ppt/.rtf` à télécharger. Documents convertis sans `innerHTML` ; XML avec DOCTYPE/ENTITY refusé ; limites de taille.
- **Images** : zoom, déplacement, rotation, plein écran, diaporama, glisser-déposer, flèches du clavier.

**Lecture en continu sans proxy** : `sw.js` (service worker de votre propre site) récupère le fichier WebDAV directement, avec vos identifiants gardés **en mémoire seulement**, par morceaux (Range). Si le serveur n'expose pas `Content-Range`, repli automatique sur un téléchargement complet.

## Barre des tâches, bureau, applications web
- **Barre des tâches** : *App Store*, **Mes apps**, **IA**, **Lecteurs WebDAV**, le bouton **Démarrer**, puis à droite le compte, la **sauvegarde dans le cloud**, la **mise en veille (verrouillage)** et l'horloge. Les autres outils (Navigateur, Tutoriel, Post-it, fond d'écran, réglages, à propos, plein écran) sont dans le menu **Démarrer**.
- **Lecteurs WebDAV** : fenêtre d'accès rapide listant les stockages connectés (icône du fournisseur, ouverture directe, site du fournisseur, raccourci bureau) avec un bouton **Ajouter un lecteur WebDAV**.
- **Fenêtres ouvertes en grand** : l'explorateur WebDAV, *Mes apps*, l'*App Store*, la fenêtre *IA* et les applications web ouvertes dans le bureau s'ouvrent agrandies en **vrai plein écran** (la fenêtre couvre tout l'écran ; la barre des tâches reste visible et cliquable par-dessus, le contenu s'arrête juste au-dessus d'elle) (bouton « Agrandir » pour revenir à la taille normale). Les lecteurs et les autres applications intégrées gardent leur taille normale.
- **Mes apps** : vos raccourcis web (par catégorie) en haut, puis les applications intégrées en bas ; contient les applications intégrées (non supprimables, avec raccourci bureau) ; elles ne sont **pas** dans l'App Store. Une app installée depuis l'App Store peut être **désinstallée** (icône corbeille) ; elle reste alors dans le catalogue de la boutique.
- **Plein écran** : le bouton de la barre met le bureau en plein écran ; **Échap** (géré par le navigateur) revient à la normale, comme un second clic sur le bouton.
- **Clic droit sur le bureau** : *Mes apps*, *Applications IA*, *Lecteurs WebDAV*, *Post-it*, *Tutoriel (PDF)*, ajouter une application, ajouter un lecteur WebDAV, *Relais…*, fond, réglages. Échap ou un clic ailleurs ferme le menu.
- **Raccourcis du bureau** : chaque application, chaque stockage WebDAV, chaque raccourci web peut être posé sur le bureau ou retiré.
- **Navigateur** (bouton de la barre des tâches ou *Mes apps*) : mini navigateur dans une fenêtre, avec **onglets**, barre d'adresse, **précédent / suivant / actualiser / accueil**, **zoom** (50 à 200 %, clic sur le pourcentage pour revenir à 100 %), **Ouvrir dans un nouvel onglet du navigateur** et **Copier l'adresse**. La fenêtre s'ouvre en **plein écran** (la barre des tâches reste visible) ; « Agrandir » la ramène à une fenêtre que l'on **redimensionne** en tirant sur ses 4 bords et ses 4 coins (taille minimale 420 × 300 px) et que l'on déplace par sa barre de titre. **Glisser-déposer** : tirez une adresse (icône ou texte de la barre d'adresse de Chrome / Edge, un lien d'une page) sur la fenêtre : elle s'ouvre dans un nouvel onglet du navigateur interne (un voile « Déposez l'adresse ici » couvre le site pendant le glissement). Seules les adresses http(s) sont acceptées. La page d'accueil propose vos raccourcis web. Un site s'affiche dans la fenêtre (simple `iframe` isolé) **seulement s'il l'autorise** ; sinon (Google, YouTube, GitHub, Wikipédia… ou adresse `http://`) un message propose **Ouvrir dans un onglet**, avec « Essayer quand même » et « Toujours dans un onglet » (mémorisé dans votre profil, comme pour les raccourcis). Des mots saisis dans la barre ouvrent une recherche DuckDuckGo dans un onglet (les moteurs refusent l'affichage intégré). Pas de favoris.
  **Limites honnêtes** : le navigateur ne peut ni lire le titre d'une page d'un autre site ni suivre les liens cliqués dans la page ; *Précédent / Suivant* parcourent donc les adresses ouvertes **depuis la barre, l'accueil ou un raccourci**, pas les liens suivis dans le site. Aucun historique ni cookie n'est enregistré par l'application.
- **Applications IA** : dans l'App Store, choisissez *Type : application IA*. Elle apparaît alors dans la fenêtre du bouton **IA** (et pas dans *Mes apps*). Mêmes modes d'ouverture que les autres apps.
- **Mode d'ouverture** de chaque app web : **automatique** (par défaut), **toujours dans le bureau** ou **toujours dans un onglet**. Un navigateur ne peut pas savoir à l'avance si un site interdit l'affichage intégré (en-têtes `X-Frame-Options` / CSP illisibles) : la détection automatique est une heuristique (sites connus, sites déjà basculés en onglet, adresses `http://`). Ces sites s'ouvrent dans un onglet avec un bouton **Essayer dans le bureau** ; pour les autres, la fenêtre propose toujours *Ouvrir dans un onglet* et *Toujours dans un onglet*.
- Icônes : détectées depuis le site (`/favicon.ico`, puis le service d'icônes DuckDuckGo, désactivable dans Réglages) ou importées par vous.

- **Caster** (lecteurs musique et vidéo) : un site web ne peut pas ouvrir lui-même la fenêtre de diffusion du navigateur. Le bouton **Caster** n'envoie rien : il affiche en une phrase le chemin à suivre (Chrome : menu ⋮ → « Caster… » → « Caster l'onglet » ; Edge : menu « … » → « Enregistrer et partager » → « Caster le média sur l'appareil »). Si Chrome déplace ce menu, le bouton **Chercher le tutoriel** ouvre une recherche Google (nouvel onglet) avec les mots-clés pour retrouver la marche à suivre à jour. Aucune donnée n'est envoyée à Google, sauf cette recherche lancée par vous.
- **Playlist vidéos** : gardez les **liens directs** de vos vidéos (n'importe quel fournisseur) avec leur **miniature**. Un clic sur la photo ouvre le lien dans un **nouvel onglet**. Catégorie choisie à l'ajout (modifiable, y compris en lot), **barre de recherche** (titre, catégorie, site ; sans tenir compte des accents ni des majuscules ; plusieurs mots), filtre par catégorie, tri, sélection multiple, suppression à tout moment (lien **et** miniature, avec confirmation). Capacité : **5 000 vidéos**, affichage par pages de 48 (« Afficher plus ») pour rester fluide. La miniature se choisit (fichier, glisser-déposer, Ctrl+V, adresse d'image) ; pour un lien YouTube elle est récupérée automatiquement si le navigateur y parvient. **Stockage** : liens et titres dans votre profil chiffré ; miniatures dans le navigateur (IndexedDB), par utilisateur, **non chiffrées**, incluses dans la sauvegarde cloud (*Sauvegarder maintenant*). Pas d'export de fichier : la playlist, les miniatures et les raccourcis voyagent par votre cloud. La suppression d'un compte efface ses miniatures.
- **Tutoriel (PDF)** : le bouton **Tutoriel** de la barre des tâches (et le clic droit sur le bureau) affiche **votre** PDF dans une nouvelle fenêtre. Au premier clic vous choisissez le fichier ; il est enregistré **non chiffré** dans ce navigateur, pour votre compte (inclus dans la sauvegarde de votre cloud ; absent du dépôt public). Pour le mettre à jour : **Réglages → Tutoriel (PDF) → Choisir / remplacer le PDF…**, ou **Retirer**. 80 Mo maximum.
- **App Store** : fenêtre à part (violet/orange, logo « App Store Sormick » en tête, **ouverte agrandie**) qui fonctionne comme une vraie boutique (Windows / Android) : vous y **listez à la main** les applications cloud (nom, adresse web, catégorie, description, icône) ; elles ne sont **visibles que dans la boutique**. Le bouton **Installer** les rend disponibles dans **Mes apps** (ou **IA**) et sur le bureau ; **Désinstaller** les en retire sans les supprimer du catalogue. Onglets *Boutique* / *Installées*, filtres par catégorie, recherche. Modifier une app du catalogue met aussi à jour sa copie installée. Le catalogue est propre à chaque utilisateur (clé `vd2.s.<id>`), sauvegardé, exporté et synchronisé avec le profil. L'ouverture des apps installées (`launch`) est inchangée.

- **Logo et icône d'onglet** : le logo sormick Cloud est affiché en grand dans **À propos** (sur une pastille blanche, lisible quel que soit le thème) ; `favicon.png` est l'icône de l'onglet du navigateur. Le titre de l'onglet reste « sormick Cloud — PC virtuel ».
- **Avatar** : à la création d'un utilisateur, on choisit un avatar (12 emojis, l'initiale du nom, ou **sa propre photo**, recadrée au centre et réduite à 96×96 px). Il s'affiche sur l'écran de connexion, dans la barre des tâches et dans « Mon compte » (où on peut le changer : *Changer mon avatar*). Il est enregistré **avec la liste des profils, donc non chiffré** (il doit être visible avant la saisie du mot de passe) : n'y mettez rien de sensible. Il suit l'export / import du profil.

## Cover des films (lecteur vidéo)
À l'ouverture d'une vidéo, le titre déduit du nom du fichier est cherché sur **IMDb** (service de suggestions public, sans clé ni réglage) et l'affiche du premier résultat est associée à ce fichier ; elle s'affiche en grand à droite du lecteur (à part : elle n'est jamais intégrée à la vidéo et n'empêche pas sa lecture). Si l'affiche ne correspond pas : **Changer le cover…** → saisissez le titre (en français) → **Choisir**. Seul le titre cherché est envoyé à imdb.com ; seule l'**adresse** de l'image est conservée (profil chiffré). Les images restent la propriété d'IMDb et sont affichées depuis leurs serveurs. Ce service n'est pas une API officielle : s'il change ou refuse l'accès, le lecteur fonctionne normalement, sans cover.

## Sormick Radio
Radios du monde : **Découvrir** interroge en direct l'annuaire communautaire **Radio Browser** (radio-browser.info) avec des filtres **langue / genre / pays** modifiables à volonté et une recherche par nom ; seules les radios en https sont affichées (un site https ne peut pas lire un flux http). **Mes radios** : vos propres adresses de flux (ajout, modification, suppression), classées par langue et genre de votre choix (*Renommer langue / genre* change une catégorie pour toutes les radios). **Paroles** : le panneau « Paroles de la chanson » affiche les paroles du morceau en cours, cherchées sur **LRCLIB** (lrclib.net, base libre et gratuite, sans clé). Le titre en cours est lu dans le flux de la radio (métadonnées ICY) quand le serveur de la radio l'autorise depuis un site web (cas d'Icecast) ; sinon, saisissez « Artiste – Titre » et cliquez *Chercher les paroles*. Seul ce texte est envoyé à LRCLIB. Les radios de l'annuaire se modifient aussi directement (crayon à côté de l'étoile : nom, adresse, langue, genre, pays) : la version modifiée est enregistrée dans *Mes radios* et remplace l'originale ; la supprimer de *Mes radios* rétablit l'originale, import / export (JSON, M3U, PLS), quelques radios d'exemple. **Enregistrer** : le flux est copié par morceaux (un seul fichier ou un fichier toutes les 5 à 60 minutes) vers le **stockage WebDAV et le dossier de votre choix** (ou téléchargé sur l'appareil). Si la radio n'autorise pas la lecture depuis un site web (CORS), l'enregistrement passe par le **relais**. Le flux est gardé en mémoire jusqu'à l'envoi du morceau : fermer la fenêtre arrête et envoie.

**Titre en cours, paroles, pochette** : le titre est lu dans les métadonnées ICY du flux (si le serveur de la radio l'autorise). Il est **nettoyé** (numéro de piste, « (Official Video) », « feat. … », année) et essayé **dans les deux sens** (Artiste – Titre / Titre – Artiste, certaines radios inversent) ; les résultats LRCLIB sont **classés par ressemblance** (accents et ponctuation ignorés) et le meilleur est affiché en premier (♫ = paroles synchronisées). Quand les paroles sont synchronisées, la **ligne chantée est mise en valeur** et défile : le suivi démarre au changement de titre (décalage réglable −1 s / +1 s) ; pour un morceau déjà commencé à la connexion, cliquez sur la ligne chantée pour caler le suivi. La **pochette de l'album** (ou la photo de l'artiste à défaut) s'affiche **à droite des paroles**, et en miniature à côté du titre quand le panneau est fermé.

## Sormick TV (IPTV / M3U)
**Catalogue** : les listes M3U publiques du projet **iptv-org** (github.com/iptv-org/iptv, licence CC0) classées par **langue**, **catégorie** ou **pays**, chargées à la demande. **Mes listes** : vos propres adresses M3U (nom, adresse, langue ; modifiables) et ouverture d'un fichier `.m3u` de l'appareil. **Mes chaînes** : favoris modifiables. Les chaînes des listes se modifient aussi directement (crayon à côté de l'étoile) : la version modifiée est enregistrée dans *Mes chaînes* et remplace l'originale ; la supprimer rétablit l'originale. **Sous-titres** : si la liste HLS d'une chaîne annonce des pistes de sous-titres (WebVTT), elles sont téléchargées par le site et affichées automatiquement (langue de l'interface en priorité), avec un choix de piste et un décalage ±0,5 s pour les directs. **Guide des programmes (EPG)** : fichier XMLTV (.xml ou .xml.gz, 60 Mo max.) saisi dans le panneau « Guide des programmes » (enregistré dans votre profil chiffré) ou annoncé par la liste M3U (`url-tvg`) ; il affiche le programme en cours et les suivants de la chaîne choisie (rapprochement par `tvg-id`, ou par nom). Lecture HLS native du navigateur (Chrome, Edge, Safari) ; les chaînes en http sont masquées (bloquées par le navigateur) ; beaucoup de flux publics sont instables ou protégés. **Enregistrer** : copie du flux HLS (ou direct) par morceaux vers votre WebDAV (qualité basse / moyenne / haute pour les chaînes multi-qualités) ; fichiers `.ts` / `.mp4` à lire avec VLC. Les flux chiffrés (AES-128) ne peuvent pas être enregistrés. Les flux sans CORS passent par le relais (consomme son quota).

**Guide des programmes (EPG)** : sur chaque chaîne, « ▶ programme en cours » s'affiche dès que le guide du pays est chargé (automatiquement à l'ouverture d'une liste par pays ou par langue ; le guide annoncé par la liste elle-même est aussi utilisé). Format **XMLTV** (`.xml` ou `.xml.gz`, 60 Mo max décompressé). La correspondance se fait par identifiant `tvg-id` puis par nom de chaîne (accents, « HD », « FR »… ignorés). Sources du catalogue : **EPGShare** (epgshare01.online, un guide par pays) et **epg.pw**. Le bouton **Guides par pays…** ouvre le catalogue, **entièrement modifiable** (modifier l'adresse d'un guide, en ajouter, en retirer, tester, *Rétablir le catalogue d'origine*, importer un catalogue JSON distant `[{"name":"…","cc":"fr","url":"https://…xml.gz"}]` pour le mettre à jour sans toucher au code). Un guide « manuel » peut aussi être saisi dans le panneau EPG. Aucune donnée personnelle n'est envoyée.

Remplace l'ancienne application « Dessin » (même emplacement d'enregistrement : *Enregistrer dans…*). Tout est écrit à la main, sans bibliothèque externe, et tourne dans le navigateur.

## Contact

## Ce que contient le dépôt public (et ce qu'il ne contient pas)
- **Aucun mot de passe, jeton, clé ni donnée d'utilisateur** : tout ce qui est secret (identifiants WebDAV, clé OpenSubtitles, notes, playlists) reste dans le navigateur de chaque utilisateur, chiffré avec son mot de passe.
- `config.js` ne contient **plus** l'adresse du relais (champ vide) ni aucun jeton : ils se saisissent dans l'application et vivent dans le profil chiffré. Il ne reste que l'adresse de contact, **brouillée** (inversion + base64) : c'est de l'**obfuscation, pas du chiffrement** (le navigateur doit pouvoir la lire) ; elle évite seulement l'aspiration automatique d'adresses e-mail.
- Les connexions WebDAV (adresse, utilisateur, mot de passe, icône) sont saisies dans l'application, jamais dans le code.
- Quelqu'un qui télécharge le dépôt obtient l'application, pas vos données : sans le mot de passe d'un profil, un profil exporté ou le stockage du navigateur est illisible (AES-256-GCM).
- Avant de publier : vérifiez que `.gitignore` est bien envoyé et ne mettez jamais de mot de passe, de jeton Cloudflare ou de fichier de profil exporté dans le dépôt.

## Passerelle facultative
```bash
npm install
PROXY_TOKEN="$(openssl rand -hex 24)" ALLOWED_ORIGIN="https://<utilisateur>.github.io" npm start
```
À placer derrière HTTPS, puis : *Réglages → Passerelle* (adresse + jeton, chiffrés dans votre profil). Variables : `PORT`, `ALLOW_PRIVATE_HOSTS` (ex. `nas.local`).
Elle ajoute : WebDAV sans CORS (mais sans lecture en continu), et affichage dans le bureau de certains sites qui interdisent l'intégration (relais, avec des limites : seuls les clics sur liens sont réécrits).

## Sécurité du code
CSP stricte (pas de script inline), aucune donnée externe injectée via `innerHTML` (le HTML de l'éditeur passe par une liste blanche), adresses limitées à http(s), iframes en `sandbox`, fichiers lus en blob avec type MIME imposé, enregistrements chiffrés avec un nouvel IV à chaque écriture et authentifiés (toute modification du fichier est détectée), ralentissement après échecs de connexion.

## Contributions externes : qu'est-ce qui reste à risque ?
Avec ce fonctionnement, quelqu'un qui consulte ou copie le dépôt public n'y trouve **ni adresse de relais, ni jeton, ni identifiant WebDAV** ; son propre déploiement (autre adresse de site) a de toute façon un stockage de navigateur séparé du vôtre, et votre relais refuse les sites autres que le vôtre (et, avec le jeton, toute requête sans jeton). Pour tester une fonction, un contributeur saisit **ses propres** informations de connexion dans **son** copie de l'application.
Le risque qui demeure est le **code que vous publiez vous-même** : une modification malveillante fusionnée dans votre site s'exécuterait dans votre navigateur et pourrait lire vos données déchiffrées (identifiants, jeton) pendant votre session. Donc : relisez chaque proposition de modification avant de la fusionner, activez la protection de la branche `main` (GitHub → Settings → Branches : « Require a pull request before merging »), ne donnez pas d'accès en écriture au dépôt, et utilisez des mots de passe d'application révocables chez vos fournisseurs WebDAV.

## Le relais peut-il afficher dans le bureau un site qui interdit l'intégration ?
**Non, pas de façon fiable, et ce n'est volontairement pas fait.** Un site qui refuse l'affichage dans une fenêtre (en-têtes `X-Frame-Options` / `frame-ancestors`) le fait pour se protéger. Un relais pourrait retirer ces en-têtes, mais la page chargée ainsi ne fonctionnerait pas : connexion (cookies tiers), scripts et appels réseau y échouent presque toujours (Google, YouTube, GitHub, réseaux sociaux, la plupart des assistants IA). Cela transformerait aussi votre relais en proxy web généraliste. Solution retenue : ces sites s'ouvrent dans un **onglet** (mode automatique, ou « Toujours dans un onglet »). La passerelle facultative auto-hébergée (`server.js`, Réglages) tente un affichage réécrit avec les mêmes limites ; elle est inutile pour WebDAV puisque le relais Cloudflare existe.

L'enregistreur d'écran demande du MP4 au navigateur et ne passe en WebM que si celui-ci n'en sait pas faire (ex. Firefox).
- **Menu Démarrer** : comme sous Windows. À **gauche** « Bureau et outils » (Navigateur, Tutoriel, Post-it, Fond d'écran, Réglages, À propos, Plein écran), à **droite** « Épinglées » : les applications que vous avez épinglées depuis **Mes apps** (bouton *Épingler* / *Désépingler*, ou la croix sur l'icône dans le menu). Le menu grandit avec le nombre d'épingles et la colonne de droite **défile** quand il y en a beaucoup. Une recherche en haut du menu trouve toutes les applications. La liste des épinglées est enregistrée dans le cloud avec le profil (elle suit votre compte d'un PC à l'autre). Échap ou un clic ailleurs ferme le menu.
- **Description automatique** : dans l'App Store, en saisissant l'adresse d'une nouvelle app (ou « Détecter icône et description »), le nom, la description et l'icône sont cherchés en 3 étapes : (1) la page d'accueil lue directement, ou **via le relais** du site si le site refuse la lecture (balises *description*, Open Graph, Twitter, JSON-LD) ; (2) la page d'accueil du domaine si vous avez saisi une sous-page ; (3) le service en ligne **Microlink** (sans clé, il lit la page côté serveur comme le font les gestionnaires de favoris ; quota gratuit limité par jour). L'étape 3 envoie l'adresse du site à ce service : elle se désactive dans Réglages. Si rien n'est trouvé, le message en donne la raison (site qui refuse, quota atteint, service désactivé…) et la description reste à saisir à la main.
- **Programmes locaux (App Store → « Programme local »)** : un site web ne peut **pas** lancer un programme Windows directement. Deux solutions : (1) un **lien d'application** déjà connu de Windows (`steam://rungameid/440`, `ms-settings:display`, `spotify:`, `vscode://`…) — le navigateur demande l'accord puis Windows l'ouvre ; (2) un **programme .exe** : on donne son chemin complet, l'application fabrique un petit fichier `.reg` à **double-cliquer une fois par PC** qui relie un lien `sormick-nom-xxxxx://` à ce programme (aucun argument n'est transmis, les programmes système comme cmd ou powershell sont refusés, et la clé n'est écrite que pour votre session Windows). Pour éviter de saisir le chemin, **glissez dans la fenêtre le raccourci Windows (.lnk) du programme** (bureau ou menu Démarrer de Windows) : le chemin complet est lu dans le fichier, dans le navigateur, sans rien envoyer. Un `.exe` glissé directement ne donne que son nom (un navigateur ne révèle jamais le chemin complet d'un fichier) ; astuce : Maj + clic droit → « Copier en tant que chemin ». Pour une **application du Microsoft Store** (ou n'importe quelle application listée par Windows), choisissez le type **AppID** : dans PowerShell, `(Get-StartApps | Where-Object Name -like "*Nom*").AppID` donne l'identifiant ; collez-le (ou la ligne `explorer.exe shell:AppsFolder\<AppID>`) ; deux boutons **Copier** évitent de retenir les commandes (trouver l'AppID avec le nom saisi, et lancer l'application avec cet AppID) et le `.reg` généré lance cette application via `explorer.exe`, sans aucun argument variable. Le programme est ajouté à la **boutique**, puis **Installer / Désinstaller** comme les autres apps (enregistré dans le cloud, épinglable, sur le bureau). Un site ne pouvant pas modifier le registre Windows, **désinstaller ou supprimer** un programme local propose le **fichier de retrait (.reg)** à double-cliquer pour effacer le lien de ce PC (bouton *Retrait .reg* aussi dans Mes apps). Sur un autre PC, le bouton **Fichier .reg** refait la liaison. Les liens `http`, `javascript:`, `file:`… sont refusés.
- **Filtre par catégorie** : un **panneau de catégories** à gauche (liste avec le nombre d'applications, qui défile ; avec un champ « Chercher une catégorie… » au-dessus) dans l'**App Store**, **Mes apps** (avec *Applications intégrées*) et la fenêtre **IA**. Il se combine avec la recherche. Dans une fenêtre étroite, la liste devient une bande horizontale au-dessus.
- **Langue automatique** : à la **première visite** (aucun choix enregistré), le site prend la langue du navigateur si elle fait partie des langues proposées (sinon le français) et la mémorise. Le menu des langues reste prioritaire : un choix manuel n'est jamais écrasé.
- **Apps cloud / Apps locales** : deux onglets bien visibles en haut de l'**App Store** et de **Mes apps** séparent les sites web des programmes de ce PC ; ils ne se mélangent jamais. Les applications intégrées restent dans l'onglet *Apps cloud* (catégorie « Applications intégrées »). Le bouton *Ajouter à la boutique* est dans l'onglet cloud, *Programme local* dans l'onglet local.
